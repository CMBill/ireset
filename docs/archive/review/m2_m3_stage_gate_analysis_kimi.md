# M2-M3 收尾阶段门未达标原因分析(2/6 < 4/6)

日期:2026-09-17。分析对象:[m2_m3_completion_plan.md](../plans/m2_m3_completion_plan.md) 阶段 3 重测(v4,阶段 1+2 组合)后的**阶段门判定**。证据来源:[m2_m3_completion_verification.md](../verification/m2_m3_completion_verification.md) §4-5、`derived/data/teachers_regenerated/pilot_diagnosis6_v4_stage12/`(逐段 frame_log + regen_report)、`src/ireset/repair/{scp,pipeline}.py` 实现核对。

## 1. 结论

阶段门要求 ≥4/6 保留,实测 **2/6**(sub10、sub8,与 v3 相同两段),四段失败段 **0 转化**。阶段 1(动态 pair 激活)/阶段 2(插值走廊语义)两项修复本身有效且均被实证——失败帧后移(sub3 t=1→11、sub7 t=24→34)、插值走廊误拒类别消除、标准模式 4/6 零回归——但每段在"检查层 bug"之下还压着一层独立的、属于真实可行性/数据性质的败因。阶段门隐含假设"四段失败中至少两段由已修的两类 bug 引起",该假设被证伪。按方案 §7 门禁停止扩展是正确执行,不是异常。

补充细节:

- sub7 的 t=24 在 v4 下能通过,代价是当帧从 52.6mm **单步跳入 −1.49mm**(54mm 闭合,probe motion 81mm);走廊上界公式 `max(gap, prev − rate·dt − margin)`(`scp.py:455-457`)只约束端点闭合下限速度,不限制单帧闭合幅度,且阶段 2 后探测行不再携带走廊上界。随后区间激活(upper 固定 8mm),进入持续贴边求解。

- sub12 的拒绝耗时 1.6s/3 帧,相对 v3 的拖到 t=11 属于"诚实快拒";这符合修复意图(不可行输入尽早拒绝),但不产生接受率。

## 3. 共性根因

**3.1 双层失效结构:修复有效但不充分。** 阶段 1/2 修的是检查层假象(pair 集合在 `z_init` 冻结导致漏检回流缺失;插值中态继承帧末走廊上界导致误拒)。v3 的部分败因确实由此造成(sub7 t=24 的 −23mm 求解候选穿透、sub3 t=1 的脚部失败),修复后这些帧通过。但四段各自的第二层原因全部落在"求解器在大步/贴边帧的可行性"与"输入数据本身不可行"上——方案 §2.2 已预警"局部机制判断不等于所有失败都可修复",实测如此。

**3.2 regen 模式的结构性张力是 sub3/sub7 的共同根源。** 参考人体接触计划要求抓握的帧里,G1 教师手实际悬浮(已知 p95 ~33mm;sub7 极端到 48mm)。regen 行用硬区间 [−1.5mm, +8mm] + 0.15m/s 闭合走廊(`scp.py:431-458`)强制消化这个矛盾,求解器每帧贴在约束边界上,任何大运动帧或箱体加速帧都会把线性化系统推到预算内无解。

**3.3 "infeasible" 不是形式化不可行证明。** `scp.py:900` 的 `status="infeasible"` 是"40 迭代 + 信赖域坍缩 + slack 恢复后仍未到可行点"的兜底分支。三起点(prediction/prev_accepted/slack_fallback)一致失败是强证据,但不排除更好的策略(跟踪权重、软拉入、探测点约束)能找到可行点——这正是方案 §7 阶段 4 条件项存在的理由,也支持"按剩余证据分流"而非"判死"。

**3.4 诊断集是失败富集集,外推需谨慎。** 六段为诊断挑选的难段,2/6 不能直接外推到 24/312 段的预期接受率;但阶段门定义在该难集上,未达标即停止扩展,结论不依赖外推。

## 4. 保留段的隐性代价(与接受率同等重要)

阶段 2 放开中态走廊上界后拉入更快、箱系速度抖动增大,准静态进入门(0.05 m/s)更难触发:**sub10 认证区间 3+2 帧→0、接触 R 0.905→0.838**(74 帧中 5 帧失物理接触);sub8 接触 R 0.988→0.975。keep 判据用的是物理接触覆盖,两段仍 keep,但**保留段作为训练标签的可用性弱于 v3**。"接受率"与"认证覆盖"存在真实张力:单纯追接受率会以标签质量为代价,24 段标定前必须恢复认证覆盖或给出明确可用性结论。

## 5. 后续优先级建议

1. **先解决 sub10 认证覆盖退化**(方案 §7 行 5)——它影响已保留段的标签可用性,是 24 段标定的前置阻塞,优先级高于新增接受段。
2. **sub16 → 探测点约束**(§7 行 1):唯一一段"端点已感知 pair 但中态仍败",机制最清晰;须配雅可比有限差分对拍。
3. **sub3/sub7 → 贴边帧软拉入/t=0 走廊下界消融**(§7 行 3):两段同族,可合并设计对照;同时记录对 sub10 认证覆盖的影响(拉入策略与抖动直接相关)。
4. **sub12 → 输入证据筛查**(§7 行 4):120mm/帧滑步用原始站点速度即可预注册判定,不应消耗求解器预算;排除仍计入原始分母。
