## 1. 结论摘要

六段仍为 **2/6 保留，低于 ≥4/6 阶段门**。但不能将结果简单解释为“阶段 1、2 已完成正确性修复，剩余仅为阶段 4 的策略能力不足”。

只读检查实现、逐帧日志及低成本数值复现后，发现四层问题：

1. **阶段 1 的碰撞对回流存在类型污染**：主动手部行以 `regen` 类型回流后，覆盖原始 `robot_box` 分类，导致走廊换选或消失。
2. **sub12/sub16 仍存在端点可行、插值路径碰撞**：原验证文档“四段全部收敛为端点 state_constraints”的归因不符合尝试级日志。
3. **QP 跟踪目标线性项存在重复尺度归一化**：装配与实际 objective 梯度不一致；sub3/sub7 的局部求解失败不能直接视为原非线性任务无解。
4. **sub10 抓握认证退化真实存在**：连续低速区间消失；但不能未经单项消融就归因于阶段 2“拉入更快”。阶段 1 的类型污染已在该段覆盖损失中出现直接证据。

此外，阶段 0 的 QP/迭代汇总仍遗漏失败尝试和部分重试。

**建议顺序：先修正确性与诊断口径，再重测六段，最后按剩余证据进入阶段 4；不放宽 strict 容差，不扩展到 24/312 段。** 已有 109 项测试通过不能替代上述未覆盖契约的验证。

## 2. 分析范围与证据边界

本轮执行：

- 读取方案、验证记录、实际实现和 v3/v4 报告。
- 检查日志大小和记录数量后，按失败帧、attempt/check/probe 类型定向提取。
- 使用项目 `uv run --locked python`，在内存中复现固定状态的 pair 回流行为。
- 复算原始教师场景运动量、手部距离及尝试级 QP 次数。
- 对 sub10 v3/v4 输出进行独立终检和手部箱体系运动复算。
- 对实际 `build_qp` 与 `objective` 做隔离目标的有限差分核验。

本轮**没有修改生产代码或原始数据，没有启动完整六段重生成，没有执行修复后的接受率对照**。因此，本文件区分已确认的实现缺陷、直接失败机制和仍需消融验证的因果贡献。不得将建议写成已验证改善。

## 3. 已确认缺陷：违规 pair 回流破坏原始几何类型

### 3.1 代码链

1. 主动接触行将身份写成 `(ga, gb, "regen")`：[scp.py:479–485](../../../src/ireset/repair/scp.py#L479-L485)。
2. 检查器将违规行身份原样交给 `note_discovered_pairs`：[pipeline.py:238–248](../../../src/ireset/repair/pipeline.py#L238-L248)。
3. `_scan_pairs` 先装入 `_extra_pairs`，遇到相同 `(ga, gb)` 时跳过注册表条目，原 `robot_box` 类型不会恢复：[scp.py:327–338](../../../src/ireset/repair/scp.py#L327-L338)。
4. 最近手部几何选择只接受 `kind == "robot_box"`：[scp.py:432–442](../../../src/ireset/repair/scp.py#L432-L442)。

因此，刚发现违规的手部 pair 虽然保留在集合里，却失去主动接触行资格。它随后可能作为无接近上界的普通行存在；走廊会改选其他手部几何体，甚至完全消失。

### 3.2 固定状态复现

输入：sub7 原始教师 t=34；固定机器人和箱体状态，右手参考 hold 为真，前帧距离设为 5 mm。重复调用 `constraint_rows(..., mode="accept")` 与违规 pair 回流，不改变姿态。

| 检查 | 右手主动接触行 | 原 rubber pair 的约束 |
|---|---|---|
| 第 1 次 | rubber：8.779790 mm，upper=8 mm | 主动接触上界存在 |
| 第 2 次 | thumb：23.248173 mm，upper=8 mm | 下界 −1.8 mm，上界 INF |
| 第 3 次 | 右手 corridor 消失 | 下界 −1.8 mm，上界 INF |

**同一状态的接触要求随检查历史改变，违反了回流应保持几何分类和约束语义的契约。**

### 3.3 真实轨迹证据

sub10 v4 t=90：

- 首次检查右手距离 **43.149438 mm**，违反 **8 mm** 上界，回流 `right_rubber_hand_link~largebox:regen`。
- 后续检查右手距离完全相同，但 `corridor={}`、`viol=0`。
- 求解记录为 `accepted=true`、`iterations=1`、`qp_calls=0`、`outcome_frame_valid=true`。

见 [sub10 日志:8904–8969](../../../derived/data/teachers_regenerated/pilot_diagnosis6_v4_stage12/frame_log_sub10_largebox_000.json#L8904-L8969)。这不是通过运动满足了接触要求，而是相关要求在回流后消失。

### 3.4 影响与修复契约

该缺陷可能同时造成：

- 改选更远几何体，使求解目标突然变化或更难满足。
- 走廊消失，使局部通过不能证明预期主动接触要求得到满足。
- 接触覆盖、速度和认证指标的变化难以归因于单独的阶段 2。

应将**规范几何类型**与**行角色（regen/普通碰撞）**分开；回流使用稳定 pair 身份和原始几何类型。后续回归至少覆盖：同状态重复检查、最近手 pair 回流、候选换选、无上界退化，以及 verbose 开关不改变求解语义。

目前未做修复后对照，不能量化该缺陷对六段保留率的净影响。

因此，报告四段都显示 `skip_reason="state_constraints"`，不能推出“四段最终全部是端点失败”。

### 4.3 为什么加入端点 pair 不能解决路径碰撞

目前探测回流主要传递 pair 身份，没有将违规插值比例及该插值状态对末帧增量的梯度装入求解。

对于 sub12/sub16，端点距离合法不代表连接前后帧的插值路径合法；端点距离雅可比也不能替代探测点约束雅可比。沿同一方向做 0.75/0.5/0.25 缩步，仍可能落在碰撞区域。sub16 的日志已经展示这种情况。

因此，阶段 4 的“探测点约束/插值状态增量约束”仍有直接证据支持，但应在回流语义修正后单独验证，并做雅可比有限差分对拍。

### 4.4 sub12 的原始输入与候选运动不能混淆

复算原始 sub12 t=1→2 的 `_frame_motion_m` 为 **48.5501 mm**；日志中约 **119.7202 mm** 是已接受前帧到求解候选的场景运动量。

该指标本身也不是“教师脚部滑步距离”。因此，不能将后者写成“原始教师 120 mm/帧滑步”，也不能以此作为预注册排除原始输入的依据。当前 t=2 的失败证据不足以证明主因是长时间累积跟踪偏离。

## 5. 已确认缺陷：QP 跟踪目标线性项多除一次 D

### 5.1 数学一致性

真实目标的 prediction/temporal 项为：

\[
f(e)=w\|e/D\|^2.
\]

`build_qp` 已通过 `_unit` 得到 `r=e/D`，但随后使用 `Dinv2*r` 装配线性项：[scp.py:561–568](../../../src/ireset/repair/scp.py#L561-L568)。QP 变量是物理切空间增量，而不是归一化变量。

对直接加性分量，正确与当前线性项分别为：

\[
q_{\mathrm{true}}=2we/D^2,\qquad q_{\mathrm{code}}=2we/D^3.
\]

二次项仍使用 `Dinv2`，所以这不是整个目标统一乘常数，而是线性项与二次项不匹配。

### 5.2 实际 API 有限差分核验

以原始 sub7 t=0 状态为参考，隔离 prediction 项，关闭 mesh、temporal、regularization 权重，增加根平移 3 mm、一个关节 0.01 rad。使用实际 `build_qp`，并以 `retract_batch` 对实际 `objective(evaluate(...))` 作中心差分，步长 `1e-6`。

| 分量 | 当前 q | objective 有限差分梯度 | 比例 |
|---|---:|---:|---:|
| 根平移 | 750.000000 | 15.000000 | 50× |
| 关节 | 20.000000 | 2.000000 | 10× |

另对隔离残差模型进行解析/FD 核验，根旋转尺度 D=0.05 对应 20× 的重复缩放；这项不是完整流形 objective 的旋转雅可比验证。

### 5.3 与失败的关系及边界

错误模型可能要求过大的步长，随后被信赖域截断；不同分量的放大倍数还改变了 prediction/temporal 与 mesh/hand 目标的竞争关系。QP 模型与实际 merit 不一致，可导致线搜索拒绝和信赖域反复缩小。

sub3 三次尝试的迭代数为 **15/17/16**，sub7 为 **20/25/24**，均未耗尽 40/80 的对应预算。结合 [scp.py:844–900](../../../src/ireset/repair/scp.py#L844-L900)，退出与信赖域缩小分支一致；仅增加最大迭代数不一定触及主因。

**不能据此断言该数值缺陷单独导致四段失败。** 尚未执行修正后的逐段消融；`infeasible` 在这里是求解器返回状态，不是原非线性问题不可行的数学证明。

建议先增加 `q` 与 objective 在增量零点处梯度的一致性测试，再修正装配并重测。现有 slack 装配测试使用零跟踪残差，无法暴露此缺陷。

### 6.2 认证归零的直接机制

[validation.py:429–438](../../../src/ireset/repair/validation.py#L429-L438) 将三处手部 site 转到箱体 geom 坐标系，取逐 site 帧间速度的最大值。速度必须低于 **0.05 m/s**，距离 enter 为 **10 mm**、exit 为 **30 mm**，候选区间不足 **3 帧**会被删除。

虽然名称为 entry gate，实际速度门逐帧应用，超门也会终止已有区间。

| 手 | v3 速度 p50/p95（m/s） | v4 速度 p50/p95（m/s） |
|---|---:|---:|
| 左 | 0.06579 / 0.25036 | 0.12727 / 0.66397 |
| 右 | 0.08791 / 0.42941 | 0.15005 / 0.60433 |

v4 左手最长候选区间仅 1 帧，右手仅 2 帧，因此认证归零。原认证位置仍然可以几何接近，但速度连续性不再满足门槛。

### 6.3 不支持直接归因于“阶段 2 拉入更快”

- 两版本右手初始未接触帧相同，均为 t=21–27。
- 左手新增覆盖损失在 t=87：7.958 mm→16.772 mm。
- 右手新增覆盖损失在 t=90–94，v4 距离约为 43.149、52.120、62.210、73.733、94.718 mm。
- t=87/t=90 的日志存在回流后走廊消失；t=90 的直接证据见 §3.3。
- v4 是阶段 1+2 组合实验，没有完整单项消融。

因此，速度增大已实证，但“抖动而非更大的轨迹调整”、以及阶段 1/2 对全部速度变化的贡献仍需分离。覆盖损失主要发生在抓取尾部，不能笼统描述成初始拉入加速。

### 6.4 为什么零认证仍然 keep

当前 keep 使用每侧参考抓取帧中的**几何接近覆盖率 ≥50%**，不是认证区间覆盖率：[regenerate_teachers.py:252–259](../../../scripts/regenerate_teachers.py#L252-L259)。几何接近实际判据为最近手部 geom 距离小于 10 mm。

独立终检仍执行全局碰撞、限位及速度等检查，但手部锚漂等检查只在推断出的手部区间中执行。没有认证区间不能证明持续抓握成立。

所以：

- v4 仍满足当前几何接近筛选意义上的 keep。
- v4 抓取尾部覆盖、连续低速性及认证证据比 v3 更弱。
- v3 每侧也仅有 3 帧认证，不能作为稳定双手承重搬运已经得到验证的证据。
- “物理接触覆盖”应保守解释为几何接近，不代表受力、承重或稳定锚定。

脚本头部关于“keep 要求认证覆盖”的说明与实际实现不一致，应另行同步，但不应在修复时静默改变筛选协议。

## 8. 建议的推进顺序（未执行）

1. **先修复回流语义。** 规范几何类型与行角色分离；固定状态的检查结果不得因历史回流而放开接触要求。
2. **修复 QP 目标尺度。** prediction/temporal 线性项与目标梯度对拍，保留明确的物理增量单位；不以调权重掩盖尺度错误。
3. **修正诊断与统计。** 分别记录 skip、solver、endpoint、transition、task-quality 的失败；保留实际退出分支及最后约束证据，累计全部尝试。
4. **固定原六段与 strict 容差重新对照。** 分开报告求解成功、终检通过、几何接近筛选和认证覆盖；不能预期修正后必然达到 4/6。
5. **根据新证据实施阶段 4。** 若 sub12/sub16 仍为中间态碰撞，研究插值约束并做雅可比对拍；若 sub3/sub7 仍失败，再依据退出点约束和跟踪误差决定策略。
6. **单独验证 sub10 稳态抓取与尾部覆盖。** 先排除走廊消失，再区分参考 grip 调整、求解大步和数值抖动。v3 的少量认证不是充分的最终质量目标。

不建议当前直接采取的措施：

- 根据修复候选运动量排除原始教师。
- 将求解器 `infeasible` 当成原问题无解证明。
- 仅增加迭代预算或放宽 strict 容差。
- 将 t=11/t=34 的失败未经因果对照直接归为 t=0 下界问题。
- 在正确性和认证质量未厘清前扩展到 24/312 段。
