## 1. 目标与边界

- **V 类**(终检速度微超限,3 段):以有修正幅度上限的候选规范化与严格关节速度复核,对齐状态采纳和独立终检。
- **F 类**(6 段帧级求解失败):4 段含带行接近下界的候选证据,但尚未证明带行是唯一阻塞;另有深穿透候选和脚部速度违反。先取证,仅在 D-F 成立时实施 regen 端点带行验收界分离。
- **R 类**(sub10 系召回不足,2 段):贯通 skip 检查、远距离主动行选取、求解器提前返回和最终采纳;不把“调用 solve_frame”当作目标已参与的证据。
- **冻结值全部不变**:关节速度上限 12 rad/s、根线 1.8 m/s、根角 7 rad/s;穿透容差 −2 mm;任务工作门 0.40 m;keep 判据(每适用侧几何接近召回 ≥0.5、参考抓取帧 ≥10);strict 模式;标签协议 `graded_labels_v1`;train24 清单 `calibration24_train_v1`(哈希 `52a98507…`)与 31 test 分母。
- 冻结现有 QP 驱动界公式、探测有效界、走廊公式、权重、行预算、迭代数、信赖域与 OSQP 设置。允许的变化仅为 V1 候选规范化与采纳检查、F1 指定的 regen 端点验收界、R 类主动行参与范围与对应接受门。R 类会使原先遗漏的 pair 真正进入 QP,不能笼统声称“驱动行集合不变”。实际边界矩阵见 §2.4。
- 不新增依赖;不动 `resources/`;历史产物目录只读,新产物写入 `derived/data/teachers_regenerated/train24fix_20260927_*`。
- 数量门仍为 **≥18/24 keep**,另按 §5/§6 明确检查本轮质量回归。D 阶段结论和修复组合在正式重跑前冻结;未达标则停止并另立方案,不根据正式 train24 结果追补策略、调参或扩大候选池。

## 2. 失败证据与机理定位

以下数值取自 `labelq_20260926_train24/regen_final/regen_report_calibration24_train_v1_strict.json` 与 `train24_analysis_final.json`,并结合本次审阅的只读反例。现有证据不等于已证明每段可恢复;D 阶段(§3)补齐状态与全约束重放,再冻结修复组合。

### 2.1 V 类:终检速度微超限(3 段,`rejected_final`)

| 段 | 差分帧 | 关节(零基) | 值(rad/s) | 超限量 |
|---|---|---|---|---|
| sub7_largebox_000 | [100,101] | 26 | 12.000000401362618 | 4.0136e-7 |
| sub12_largebox_077 | [202,203] | 16 | 12.000000105688033 | 1.0569e-7 |
| sub8_largebox_048 | [11,12] | 26 | 12.000000003086466 | 3.0865e-9 |

均为 joint 族;三段都是 slack 重度段(slack 尝试 86/69/162,总尝试 119/81/206)。后缀重试(自帧 96/198/7 起)重放出**逐位相同**的超限值,证明失败可复现;具体来自哪个候选及哪次采纳仍由 D-V 绑定,不能仅从重复性推断一定是 QP 返回值。

机理(代码锚点):

1. 关节速度行(`scp.py::_fixed_pre_rows` 行 [29:58))在状态上的值为 `q - q_prev`,QP 中为 `q + dq - q_prev`,界 `±dt·12 = ±0.4 rad`。OSQP 使用 `eps_abs=3e-5, eps_rel=3e-5, polish=False`;这些是停止条件参数,受缩放和全系统残差影响,不是逐行物理误差的硬上界。slack 会进一步放松原行,且当前代码接收有限的 `maximum iterations reached` 返回值,不能据此保证误差 <=4.2e-5 rad。
2. 帧级可行性判定(`scp.py::solve_frame`:`viol = violation(val,lo,hi,scl) ≤ 1e-6`)对该行的归一化违反度为 `3.3e-8 ≤ 1e-6` → 帧被接受(验证记录 §2 已记录该定位)。
3. 独立终检(`validation.py::_check_velocities`)用严格比较:`|diff|/dt > 12.0` 即拒。速度行尺度是 0.4 rad,单行 `1e-6` 的归一化余量对应 **4e-7 rad**;sub7 实际位置越界约 1.34e-8 rad,不是可接受余量的定义。多行违反度相加后可用余量只会更小。
4. 直接 `clip(q, q_prev-dt·12, q_prev+dt·12)` 仍不保证浮点严格通过:审阅反例 `q_prev=0.8` 得到上界 `1.2000000000000002`,复算速度 **12.000000000000004 rad/s**。因此不能以“线性行可精确满足”或额外 1e-12 容差替代终检同式复核。

- −1.6 mm 相对 −1.5 mm 下界的归一化违反为 **0.05**,而不是原方案写的 `2e-4`。

现有 `_scan_pairs` 的查询上限为 6 cm,实际普通候选准入为 **distance <5 cm**;被检查发现而回流的 pair 有单独携带路径。主动 regen 行从该候选集选最近手 geom,因此远距离参考抓握可以没有主动行。`solve_frame` 又在“可行 + task 通过 + `_stationary` 接近预测”时提前成功返回。仅在 pipeline 禁止 skip 并调用求解器,不会自动让走廊或手部跟踪目标执行。

修复须同时保证参考激活侧的主动行在所有相关检查中可见,以及任何成功返回确实满足当帧走廊。合法的闭合期候选可以在尚未达到 8 mm 时满足动态上界;不能无条件把 8 mm 最终目标当作每一帧的 skip 硬门。求解次数与召回的相关性仅作诊断,不证明因果或可达性。

### 2.4 当前有效下界矩阵及唯一 F1 改动

以下均为最终装配后的有效下界,单位 mm。`m(ctx)=1000·min(0.006,max(0.0005,0.3·frame_motion_m²))`,范围 0.5-6 mm。有限上界的普通接触带指 `robot_box/robot_ground` 几何分类行;主动 regen 行另列。

| 路径 | 模式/行角色 | 当前下界 | F1 后 |
|---|---|---|---|
| 端点 QP 驱动 | standard/regen 的普通带行,以及 regen 主动行 | `-2 + m(ctx)` | 不变 |
| 端点 QP 驱动 | 非接触行 | +2 | 不变 |
| 端点验收/merit | standard 普通有限上界带行 | −2 | 不变 |
| 端点验收/merit | regen 普通有限上界带行及主动行 | −1.5 | **−1.8,仅此格改变** |
| 端点验收/merit | 任一模式非接触行 | −1.8 | 不变 |
| pipeline 插值检查 | 普通有限上界接触带,显式 margin=0 | −2 | 不变 |
| pipeline 插值检查 | regen 主动行去掉上界后,以及非接触行 | −1.8 | 不变 |

原始 `band_margin_m=0` 不能代表最终探测界:主动 regen 探测行的上界变成 INF 后,`_collision_block(...,"accept")` 会覆盖下界为 `cfg_noncontact=-1.8 mm`。端点 QP 也不是固定 −1.5 mm:运动量 0.1 m 时下界为 **+1 mm**,0.16 m 时为 **+4 mm**。这些既有语义本轮保留,不把注释中的“处处 −2 mm”当作实现事实。

## 4. 修复设计

V/F/R 分项提交并附可识别原缺陷的反例;R1/R2 共享主动行身份与接受契约,作为一个集成修复验证,不宣称两者独立。先运行聚焦测试,组合完成后运行全量测试;所有修复不动 §1 冻结值。

### 4.1 V1:有界候选规范化 + 终检同式严格复核

- [ ] 增加纯候选规范化步骤,覆盖 skip、prediction/prev_accepted/slack 候选、转移回溯候选与后缀重试。前帧固定为 `ctx.z_prev` 即实际已采纳状态;t=0 无投影。原始预测和跟踪目标保持不变,仅对待检查的候选副本操作。
- [ ] 先用与终检相同的 float64 运算 `abs(q-q_prev)/(1/fps) <= joint_velocity_limit_radps` 判断。已通过的关节逐位不动;超限关节先取对应 `q_prev +/- dt·limit` 边界,若同式复算仍超限,以 `np.nextafter(boundary,q_prev)` 向内部收缩并再次复核,最多 8 次。仍不能严格通过则该候选失败,不增加接受 epsilon、不舍入速度。
- [ ] 每候选最大绝对改变量上限固定为 `dt·limit·1e-6`(当前 **4e-7 rad**),包含 nextafter 内收。它取自旧帧级单行位置余量,是本次微量修正的独立预算,不是 OSQP 保证;不得随实测失败扩大。任一关节所需改变量超过预算时不部分投影:skip 转正常求解,求解候选按既有失败/重启流程处理,记录 `velocity_projection_budget`。
- [ ] 规范化必须发生在候选的完整接受检查之前;修改 `FrameResult.z` 时使其 `frame_check` 失效。重新检查关节限位、速度、端点、原协议全部插值点、锚点与任务门,检查后的同一状态才能提交锚点和输出。记录原候选/新候选、pass/frame/attempt/check、修正关节与幅度,避免旧检查缓存验证新状态。
- [ ] pipeline 最终帧级采纳增加独立严格关节速度判据,使用上述同式计算,不再由归一化违反总和容忍其超限。SCP 内部 merit/迭代可行性容差、QP 与 root 范数行保持原语义;solver 返回成功仍须经过规范化后的 pipeline 全检查,不能绕过新判据。
- [ ] 投影成本记录全部候选检查中的尝试/成功/预算失败与最大幅度,另记实际输出中被修正的唯一帧数;重试与未采纳候选不得漏计或混为采用数。quiet/verbose 只序列化已有结果。
- [ ] 不再从“旧标准输出过终检”推断所有中间候选均不触发投影。标准模式需实测输出、尝试和计数;差异按 §5 停止转段并核查,不能以预期无操作替代实验。
