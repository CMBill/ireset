## 2. R1：完整冻结上下文，仅切换 C2

### 2.1 快照与恢复

在既有 `fail` 快照事件同步复制最后执行尝试的候选、检查、尝试记录和 `FrameContext`。按 dataclass 字段完整复制，不再手写一个遗漏字段的子集：

- 必须保留人体 `ref_kpts_world`、`ref_hand_kpts`、`ref_hand_delta`、`frame_motion_m`，以及 mesh、预测、前帧、箱姿、锚点、参考保持和全部 C2 字段。
- NumPy 数组和嵌套字典保存独立副本；稀疏 mesh 数据保存矩阵内容、形状和索引结构。不能持有会被后续 FK 或尝试修改的数组引用。
- 反序列化恢复的上下文与快照逐字段核验，数组逐位相等；新增 dataclass 字段不能被静默漏掉。无需把此局部诊断扩展为通用序列化框架。
- 原候选、V1 规范化候选、最后线性化态和回溯态明确区分。审计以原检查实际使用的候选为准；若 V1 预算失败，则记录候选不可用，不将另一个被修正的状态冒充原候选。

`C2-off` 从该冻结上下文复制，仅将 C2 行启用状态关闭；其余字段和配置逐字段一致。原配置中的界值仍保持 0.02598，不通过替换整个配置关闭其他行为。诊断中的“反事实关闭”与“输入参考结束释放”使用不同来源标签。

### 2.2 单帧求解重放

当前 `solve_frame_escalated` 也须核对完整升级流程，不能将三个 `_solve_attempt` 调用当成完整 pipeline：

1. 每个反事实分支使用独立 evaluator/solver，从同一帧的初始 pair 状态开始。
2. 保留 V1 skip 检查；skip 失败按生产流程回流已发现 pair。
3. 依次执行 prediction、存在前帧时的 prev_accepted、配置允许时的 slack fallback；每次失败检查按既有规则回流，使用相同回溯规则。
4. 不继承原失败运行末尾的候选/探测缓存，也不遗漏新分支自身发现的 pair。恢复原冻结上下文，不用候选重新推断参考或锚点。
5. 分别保存 solver 返回状态、帧检查、最终采用与尝试/检查 ID。重解成功后对新候选执行 §4 的完整审计。

优先局部复用既有方法；如需小范围提取生产单帧升级入口，应先锁定行为等价测试，不重构整条修复流水线。

### 2.3 验收

- sub12@12、sub3@14 的任务 MPJPE 复现审阅值约 0.114154/0.131966 m，精确值由重新捕获的原上下文冻结。不能以展示舍入值作为验收 oracle。
- 快照恢复后的 `evaluate` 残差、任务误差及目标值与原上下文一致；QP 的 P/q/A/上下界与对应分支一致。
- 五段重放的失败帧、最后尝试 ID、检查 ID与正式原报告对应；若不一致，停止绑定并记录差异，不自行选择“相似失败”。

## 3. R2：区分正常截断与查询异常

### 3.1 距离返回契约

保持 distmax=1.0 m 与严格命中规则，逐 geom 检查返回：

| 返回 | 处理 |
|---|---|
| 有限且 `dist < distmax` | 真实命中，参与本侧最小距离；负值和零值保留 |
| 有限且 `dist == distmax` | 正常截断未命中；若全部 geom 均未命中，记录正常范围外状态并保持既有行关闭行为 |
| NaN、±Inf、异常抛出或不符合 API 返回范围的值 | 查询异常，记录原值或异常类型，阻止该次运行被裁决为通过 |

一侧任一 geom 异常即记为异常，即使其他 geom 有有限命中也不能忽略：失败 geom 可能是真正最近的几何体。不能把无穷值与正常截断哨兵混为一类，也不以全零 `fromto` 判断失效。

### 3.2 退出与报告

- 使用最小的显式错误传播，在 repair 的轨迹退出层返回拒绝及 `final_stage=c2_distance_query_failed`（命名可依既有结构调整）。禁止把异常转换为 `None` 后继续处理下一帧。
- 错误记录含 demo、pass、当前采集帧、side、geom 身份、distmax、原始返回值/异常和阶段。采集发生在已采纳状态上，应注明错误属于“采纳后距离采集”，不伪装成先前接受检查的失败。
- 出错时已发生的帧访问、检查、尝试和 QP 成本完整保留；不产生完整接受轨迹，不输出 keep NPZ，筛选脚本不得凭旧终检结果放行。
- 首次运行、后缀重试、最后一帧采集均传播错误；最后一帧没有后继也不能漏掉运行异常裁决。
- `_collect_prev_scene_dist` 继续受 `regen_mode and regen_hand_speed_mps > 0` 门控；标准模式和参数零路径不新增查询。
- E 工具采用相同返回契约，异常中止本次取证裁决；失败诊断可保存，不能写成“完整取证通过”。

正常 distmax 截断继续允许，不为合法远离帧增加大范围生产查询。sub16 已知 0.98–1.28 m 远离证据用于核对原分支，其部分 geom 未命中与整侧未命中须分开记录。

### 3.3 验收

自动测试覆盖 NaN、+Inf、−Inf、查询异常、一个 geom 异常而另一个有效、全部正常截断、负距/零距真实命中、最后一帧异常以及 retry pass 异常。前述三帧 NaN 反例必须从 accepted 变为显式拒绝；正常远离仍保持原结果。禁用态新增查询调用次数为零。

## 4. R3：完整候选审计与可重放证据

### 4.1 独立审计全部检查

在两个 train24fix2 工具中复用局部审计助手，优先扩展既有 `_probe_audit`。使用独立 evaluator/solver/validator；正式运行只采集快照，不为日志追加 FK、检查或回流。

对原候选 C2-on、同候选 C2-off、关闭 C2 后重解的新候选分别保存以下结果。端点失败也继续完成其余适用检查，避免生产路径的早退掩盖其他违反：

1. **输入与 V1**：形状、有限性、规范化可用性、实际检查候选、严格关节速度值/上限/超限量；不改变 V1 预算或用规范化隐藏原候选身份。
2. **端点**：fresh uncapped pair scan，fixed-pre、collision/走廊、fixed-post 的全部行，按实际描述符保存值、上下界、scale 和非负归一化违反。
3. **全部插值点**：以前一完整场景和候选完整场景计算原协议的自适应细分。每个探测点清理端点 pair 缓存并重新扫描；只判碰撞族，沿用 `probe_mode=True`、`band_margin_m=0`。记录每个点的 alpha、机器人/箱姿、全部碰撞行和裁决，包括通过的点；端点违反不能省略插值。
4. **任务**：在该候选及冻结人体参考下单独计算 MPJPE 与 0.40 m 门，保留未舍入值。先前任意 FK 状态不能改变结果。
5. **前缀独立终检**：构造本 pass 已采纳前缀加当前候选，箱姿与该 pass 输入一一对应；使用新 validator、原配置和既有 `exclude=("box_ground",)`。保存全部检查、认证区间、锚漂、最坏值和首失败帧。此结论仅覆盖前缀，不冒充剩余后缀或整段通过。

对冻结原候选使用同一个实际检查数组进行 on/off 比较；若在历史移植候选上允许 V1 规范化，则同时保存原数组与规范化数组，两分支检查同一规范化结果。新求解候选另设身份，不与原候选混合。

生产帧通过和新增完整审计通过分别记录：前者应与 `frame_valid` 对拍；后者还要求前缀终检通过。若正常短路返回，标明哪些检查未在生产阶段执行，但离线审计必须补齐。

### 4.2 接受式与分类

端点接受沿用全部有限界行的**归一化违反总和 ≤1e-6**；C2 两侧及原有行参与同一个总和。禁止将每侧/每族独立 ≤1e-6 的结果相与，代替总和判据。严格速度、任务和独立终检仍用各自原裁决。

E 阶段保留两个完整分支：当前冻结链不启用 C2、同候选仅叠加 C2。后者优先调用真实 C2 装配，冻结相同前帧/site/启用状态，不用另一套速度公式决定接受。逐分支输出端点、插值、任务、严格速度及前缀结果，再按下表汇总：

| 完整结果 | 类别与可支持结论 |
|---|---|
| 证据缺失、查询异常或身份不匹配 | `EVIDENCE_INCOMPLETE`，不进入通过计数 |
| V1 规范化不可用 | `V1_UNUSABLE`，单列原因 |
| 无 C2 完整分支通过，叠加 C2 仍通过 | `PASS` |
| 无 C2 完整分支通过，仅叠加 C2 后失败 | `C2_ONLY`，表示冻结候选的拒绝由新增行触发 |
| 无 C2 完整分支已失败 | 保留 `CURRENT_ONLY`/`BOTH` 并列出逐族违反及总和；不得称为 C2 唯一原因 |

候选 C2_ONLY、同帧重解成功、前缀通过、整段接受是四个不同结论。没有整段重跑证据，不能将前两项写成旧失败段恢复。

### 4.3 保存与重放契约

新产物使用带版本的 JSON 清单加 NPZ 数组，至少包含：

- demo、pass/frame、源尝试 ID、check ID、候选来源、实际检查状态标签、solver status/last QP status/终止信息，以及各反事实的新审计 ID。
- 原候选、实际检查候选、重解候选、已采纳前缀、前后箱姿、完整上下文、人体参考和输入参考 schedule/区间身份。mesh 稀疏矩阵保存可恢复内容。
- 每个分支的全部端点行、逐点插值行、严格速度、任务值、前缀终检及分类；行身份与数组长度一一对应，使用既有行描述符而非猜偏移。
- 代码 revision、工具源码、有效配置、输入/资产/协议、旧报告与全部引用数组的完整 SHA-256；实际线程环境、开始/结束 provenance 和漂移状态。

JSON 不写非标准的 NaN/Inf 字面量；查询错误使用 `value_kind`、异常类型和可读原值记录，必要时在 NPZ 中保存原始浮点位模式。候选数值和行值保留 float64 精度，不能用展示舍入值参与裁决。

求解候选的源 ID 必须能解析回原报告/快照。历史认证候选属于 NPZ 帧移植，保存源 NPZ/哈希/帧号，不能伪造“原运行曾执行此反事实”的 attempt/check ID。当前采纳尖峰应关联权威运行中实际采纳的状态及决定性检查；缺少来源时明确标为证据不足。

新重放命令从冻结文件恢复上下文，重新计算同候选各分支而不重新求解原轨迹；复算结果与保存结果一致。重解实验需要单独执行，记录其成本，不能把重新搜索得到的候选替代原冻结候选。

旧 E 与失败绑定目录只读。两个工具须支持显式输入/输出目录，拒绝覆盖已有取证文件；不得沿用会覆盖原 `train24fix2_20260927_diag/` 的默认写入路径。新目录约定为 `derived/data/teachers_regenerated/train24fix2_reviewfix_20261001/`，下设 `diag/`、`sixseg/{rq,rv,ns}/`。

## 5. R4：订正求解失败的结论强度

本轮不尝试证明非线性系统不可行，也不通过调参搜寻可行解。新增或导出原求解出口的事实：最后 QP 状态、SCP 实际迭代数、QP 调用数、实际终止原因、最终 trust、原预算、最小 trust、候选违反和 slack 使用情况。

`status="infeasible"` 保持历史兼容；实际终止原因从代码出口记录，不能只由该字符串反推。区分预算耗尽、信赖域过小、QP 无可用步、成功复核失败等已存在分支，不增加新升级路径。

证据和文档按以下强度表述：

| 已有证据 | 允许结论 |
|---|---|
| 原候选仅 C2 行超界，完整关 C2 分支通过 | 该冻结候选被 C2 拒绝 |
| 正确相同上下文中，现有流程 C2-on 失败而 C2-off 重解并通过完整审计 | C2 的加入使该帧在当前固定求解流程下失败 |
| `maximum iterations reached`、trust 收缩或有限预算内未找到候选 | 数值/搜索未收敛或未找到可接受解；结构性冲突仍是待检验解释 |
| 局部线性化 QP 返回不可行 | 仅说明该线性化子问题及其设置下的结果，不能推出原非线性整段不可行 |

实施时先在验证记录顶部标注审阅订正：保留 rq 1/6 与暂停裁决，撤回“完整取证已闭合”“五段联合不可行已证实”的过强断言。完成 §7 重验后填写新分类，保留旧数字及作废原因。

同步更新 `docs/archive/verification/train24fix2_verification.md` 的 §1.5、§2、§3.2–3.4，以及 `AGENTS.md` 最新进度、工程事实中对应的归因。原方案的停止规则保留，仅补充修复方案/新验证记录指针和状态。与本次 5 项问题无关的历史记录不扩大修改。

## 6. R5 与新增反例测试

### 6.1 补强原插值反例

### 6.2 其他反例

新增局部测试文件（建议 `tests/test_train24fix2_review_fix.py`），按实际覆盖报告收集数，不预先宣称固定新增数量：

| 上下文 round-trip | 把人体参考换成机器人 FK、漏手部目标/位移/运动量、后续 FK 修改快照；比较真实任务残差和 QP 块 |

| 完整审计 | 端点过但插值/严格速度/任务失败；端点失败仍收集其他检查；静态速度行过但累计锚漂导致前缀失败 |
