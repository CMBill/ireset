## 2. 数值与缓存修复

### 2.1 R1:只用有效最近点装配探测行

- [ ] 按 MuJoCo API 契约区分查询截断值与真实距离。仅将 `dist < distmax` 的返回用于当前探测行;`dist == distmax` 跳过,不得再用其 `fromto` 计算雅可比。此处是候选激活边界,不修改防穿透下界或终检阈值。
- [ ] 不以 `fromto` 全零或两点重合判定“无效查询”:真实零距离接触也会退化,应继续由 R2 处理。查询命中与接触退化是不同分支。
- [ ] 保持排序、独立探测行预算和未截断验收路径;截断统计只包含真实候选行。QP 与 merit 使用同一批有效距离,不让补丁只作用于其中一侧。

回归:用真实 G1/箱几何覆盖查询范围外、边界、范围内、穿透与零距离接触。真实范围外 pair 不产生行/雅可比/伪截断;每条保留行与较大查询范围得到的距离、最近点一致。对实际 `_probe_rows(..., need_jacobian=True)` 装配出的固定 pair/alpha 做 float64 FD,覆盖 robot-box、robot-ground 与光滑 self pair;梯度阈值沿用 `atol=1e-5, rtol=1e-3`。不能只测试绕过该装配路径的大范围距离调用。

### 2.2 R2:修正接触法向符号

- [ ] MuJoCo `contact.frame[:3]` 指向 geom1 -> geom2。所需的是 ga 的分离方向,因此 ga=geom1 时取负法向,ga=geom2 时取正法向;同步修正注释。
- [ ] 对端点与 `probe=True` 两条路径使用相同符号约定。保留无 contact record 时的既有几何回退,不扩大其适用范围或把凸体中心方向宣称为精确法向。

回归:脚球对地面分别置于零距离附近两侧,覆盖 `abs(d) < 1e-9` 且存在 contact record 的 -1e-10 m 用例、无 contact record 的零距离用例及正常非退化距离。解析根高度梯度均为 +1;交换 ga/gb 后距离梯度不变。每个 FD 扰动和几何体查询前重新 forward 到明确状态,以 1e-5/1e-6/1e-7 步长对拍;补一个具有非竖直法向的光滑接触用例,防止仅修复地面特例。

### 2.3 R3:缓存随全部探测依赖失效

- [ ] 新增 `_probe_watch` 身份时立即使探测缓存失效;每个 `solve_frame` 尝试开始和帧切换时清理旧缓存。重复登记相同身份保持幂等。
- [ ] 缓存命中不能只比较 z。核对固定前帧机器人/箱姿、当前箱姿、候选 pair 身份集合、探测配置及行预算等依赖;用本地缓存键或明确失效点覆盖它们,保存数组快照,不持有会被原地修改的引用。端点候选刷新或同一 z 下更换上下文必须重新计算。
- [ ] 缓存命中同步恢复与行对应的诊断信息,包括行名、alpha、截断项;value-only 缓存不得冒充带雅可比缓存。约束值与 QP 装配在同一依赖状态下仍可复用结果。

回归:先构造无相关探测行的缓存,保持 z 不动,通过真实 `frame_valid -> carry_discovered` 回流箱体扫掠 pair;下一次约束和 QP 必须包含新 pair。另覆盖同 z 更换箱姿/前帧、候选集刷新、跨尝试、跨帧、重复回流及 value-only -> Jacobian 升级。用直接重新查询作预期值,不把手动清缓存后的同一函数作为唯一 oracle。

## 3. 失败证据与尝试事件

### 3.1 R5:最终拒绝绑定实际最后尝试

- [ ] 将“采用的候选”与“最后执行的尝试”分开保存。prediction、prev_accepted、slack_fallback 每次完成后更新最后尝试及其检查证据;全部失败时,顶层原因、阶段、pair、probe 和 attempt ID 必须指向同一个最后尝试。
- [ ] 原始预测的 `skip_reason` 独立保留。终检失败记录 validator 的检查项与结构化帧号;如果后缀重试在求解阶段失败,保留该阶段并另记触发重试的首轮终检原因。
- [ ] 快照标明所指状态与检查阶段。求解末次线性化、返回候选、回溯候选不能混用同一状态标签。日志变更不改变候选选择或额外触发带回流的检查。

回归:控制三次尝试分别失败于端点、插值和任务门,断言最终顶层证据属于第三次。覆盖关闭 slack、t=0 无 prev_accepted、最后尝试成功、重试求解失败与两次终检失败。不能只断言 `reason_source` 的字符串或帧号正确。

### 3.2 R7:按实际块偏移描述违反行

- [ ] 明确 nonlinear 行顺序:fixed-pre、endpoint collision、fixed-post、probe。探测起点为 `N_FIXED + n_endpoint + n_post`,其中 `n_post` 从现有行数常量计算,当前为 96。
- [ ] 分块调用违反提取,或提供与完整值数组一一对应的轻量描述符。保留 pair 身份、probe alpha;固定约束用约束族及关节/site 标识,不得标成其他碰撞 pair。
- [ ] 检查描述符与值数组长度一致。QP 装配行顺序与 nonlinear 行顺序不同,不能共用未经映射的偏移。提取结果仅用于诊断,不改变 merit 或可行性。

回归:端点全过但探测失败时,精确报告 pair/alpha/值/上下界;锚点或速度单独失败时不得误报 probe。覆盖零/非零碰撞行、零/多条 probe、行预算截断和多个约束块同时失败。锁定审阅用例中的 4 条探测违反。

### 3.3 R8:事件在检查与回溯结束后定稿

- [ ] 每个求解尝试分配稳定的 `(trajectory_pass, frame, attempt_id)`;相关检查带 `check_id` 和候选来源。skip 使用独立检查事件,不伪造 QP 尝试。
- [ ] 求解返回时保存 solver 状态/成本;完成已有的检查及回溯后再定稿尝试记录。分别记录 solver accepted、frame_valid、frame_valid_reason、backtrack 探测/采用及最终采用状态,避免把 solver 成功等同于 pipeline 接受。
- [ ] `backtrack` 写实际尝试过的 alpha 及采用结果,未发生回溯时明确表示未发生。quiet 同样保留轻量事件,verbose 只序列化已有结果;失败与代表性快照按需保存。

回归:构造 solver 成功但 transition 失败、回溯成功、回溯全失败后重启三种分支。事件检查字段必须有实际值,能够关联裁决与回溯;检查次数、FK 次数、回流次数及 QP 次数在 quiet/verbose 下相同。R5 与 R8 联合验证,不为补日志额外执行 `frame_valid`。

## 4. R6:跨轮成本汇总与报告导出

pipeline 保留每轮记录,在轨迹出口形成一个明确的总计视图;脚本直接序列化该视图,避免在多个调用方重复推导。采用帧统计与总执行成本分开,后缀重试成功或失败均执行同一汇总。

| 字段族 | 总计口径 |
|---|---|
| attempts / qp_calls / iterations / slack attempts | 所有 trajectory pass 的全部尝试求和,失败尝试也计入 |
| backtrack | 分开统计探测次数和成功采用次数,不把未采用探测记为零成本 |
| processed_frame_visits | 实际进入帧处理循环的次数,包括重试重放的前缀 |
| unique_processed_frames | 所有 pass 的帧号取并集;不能把每轮去重数量相加 |
| input_frames | 原始 T,不随重试翻倍 |
| per-visit mean/p50/p95/max | 合并各轮未四舍五入的 `timings_s` 后计算,不平均各轮分位数 |
| solve / final_validation | 分别累计所有轮次的帧处理及独立终检时间 |
| adopted / slack_frames / skipped | 指明所属轮或最终输出;失败段不得伪装为完整最终输出统计 |

- [ ] 为新报告增加 schema 版本,同时导出总计与分轮明细/事件路径。旧字段若保留必须注明口径,读取端按版本处理;避免将嵌套 `first_attempt` 和已汇总总计重复相加。
- [ ] 保留 repair wall time,另计预处理、筛选、质量统计、输出和整段墙钟时间。嵌套计时注明包含关系,不能将其重复相加或把仅 repair 时间称为包含全部后处理的端到端耗时。
- [ ] 覆盖提前拒绝、首轮通过、重试通过、重试求解失败、重试终检失败所有出口。输入形状等前置拒绝应有合理的零执行计数。

回归:使用可确定触发重试的控制流用例,不能依赖“未触发则 skip”的测试。事件逐项复算总计,检查 unique/visits/T 的不同定义与拼接分位数。已有 verbose sub12 两轮日志应复算为 **130/3630/296**,unique=148、T=148;这些数字只用于旧日志审计,不能要求数值修复后的新运行仍产生相同成本。
