## 1. 结论

阶段门未达标有三类原因:阶段 1 的碰撞对回流仍存在实现缺陷;求解器没有直接约束端点之间的插值路径;几何接近尚未形成稳定的认证抓握。阶段 0 的失败定位和统计也未完全闭合,导致原记录对剩余问题的分类不准确。

- 当前实现完整重跑 diagnosis6 仍为 **2/6 保留**,四段失败帧为 sub12 t=2、sub16 t=22、sub3 t=11、sub7 t=34。
- `uv run --locked pytest tests/ -q` 实测 **109 项通过**;测试未覆盖本次发现的回流类别错误和所有成功返回分支。
- 临时实验仅将回流 pair 的几何类别恢复为注册表中的真实类别,不改 strict 容差、权重或输入,六段结果变为 **3/6 保留**,仍小于阶段门 4/6。
- sub10 认证区间归零已独立复验;临时新增通过的 sub7 也没有认证区间。保留数量与标签可用性必须分别评估。

因此应先补齐阶段 0/1,再依据新基线执行阶段 4。现有证据不支持通过放宽容差或排除原始教师来解决当前阻塞。

## 2. 已确认的实现问题

### 2.1 回流将约束行标签当成几何类别

涉及 `src/ireset/repair/scp.py` 的 `_collision_rows`、`note_discovered_pairs`、`_scan_pairs`,以及 `pipeline.py::_carry_back_discovered_pairs`。

`_collision_rows` 将主动接触行的身份写成 `(ga, gb, "regen")`。流水线把该身份原样回流,`_scan_pairs` 又优先使用回流项,跳过注册表中同一 pair 的 `robot_box` 类别。后续该 pair 不再参与要求 `kind == "robot_box"` 的主动接触选择及接触带分类,主动接触还可能转而约束另一块手部几何。

实测 sub7 原始 t=34 的 `right_rubber_hand_link~largebox`:

| 状态 | 该 pair 的 QP 距离边界 |
|---|---|
| 回流前 | [-1.5, 8] mm |
| 回流后 | [2, +infinity) mm |

这改变了约束语义。日志标签 `regen` 应与几何类别分开保存,或回流时根据 pair 注册表恢复真实类别。不能将由此造成的求解失败直接解释为接触容差过紧或输入不可恢复。

### 2.2 成功返回前全量复核未覆盖所有分支

`scp.py::solve_frame` 中,`best_z` 在全量复核前即可被保存。提前成功分支执行全量扫描,但预算耗尽或信赖域收缩后的 `best_feasible` 分支只检查任务误差,可以直接返回旧 `best_z`,没有重新完整检查碰撞。

外层流水线检查仍可拦截,本次没有发现因此输出非法轨迹的证据;但会出现求解器认为成功、流水线再次拒绝的情况,妨碍恢复与收敛。原记录“所有成功返回均已重扫”的声明不成立。

修复应统一成功返回检查,并重新验证历史 best 状态。回归测试需覆盖提前成功、预算耗尽和信赖域收缩分支。

### 2.3 失败定位、统计和日志仍有缺口

- `pipeline.py::_run_sequential` 的 `skip_reason` 来自最初预测帧的 `frame_valid`,不是最终求解候选的拒绝原因。报告不能用它判断整帧最终败于端点还是插值。
- `iterations` 和 `qp_calls` 只累计最终选中的成功结果,失败帧和被放弃的尝试未进入汇总。`attempts` 字段来自成功 slack fallback 计数,也不是总尝试次数。
- verbose 的 `_log_attempt` 会额外调用 `_frame_result_ok`,进而执行带碰撞对回流副作用的检查。日志并非纯观察操作。此次开关前后六段保留状态及失败帧一致,两条保留轨迹逐元素一致,但 sub12 QP 次数发生变化。

原 v4 报告与尝试日志的 QP 调用对照:

| 样本 | 报告 `qp_calls_sum` | verbose 尝试日志求和 |
|---|---:|---:|
| sub10 | 2050 | 2113 |
| sub12 | 0 | 70 |
| sub16 | 0 | 71 |
| sub3 | 0 | 48 |
| sub7 | 243 | 379 |
| sub8 | 291 | 331 |

新运行的 quiet 基线中 sub12 为 66 次,不是上述 verbose 的 70 次。这里应分别保留运行条件,不能混作同一统计结果。上述问题也意味着阶段 0 尚不能声明完整完成。

## 4. 对剩余失败与质量退化的归因修订

### 4.1 sub12/sub16 仍存在真实插值碰撞

原验证记录 §4 的“四段失败全部收敛到 state_constraints,无一为 transition_interpolated”不成立。它混用了预测输入的 skip 原因和候选的最终失败原因。

sub16 t=22 三次求解都返回端点成功,但插值中 `right_knee_link~right_rubber_hand_link` 发生碰撞,最深约 10 mm。日志中的端点 -5.3 mm 等数值包含回溯候选,不能据此将整次失败归为求解端点不合法。仅将 pair 回流到端点行无法保证插值路径安全。

sub12 t=2 也存在端点合法而插值手部穿箱的候选。原记录中的“教师 120 mm/帧滑步”来源不正确:重新读取原始教师,t=1→2 的最大站点/箱角点运动为 **48.55 mm**,根平移为 **10.14 mm**;约 120 mm 是已接受状态到求解候选的运动量。不能据此判定原始输入存在不可恢复跳变。类别修正后失败推进至 t=10,应基于新的状态链重新分析。

### 4.2 sub3/sub7 不应直接转向 t=0 下界策略

原记录将 t=11、t=34 的失败归为与 t=0 软拉入同族,证据不足。对应的 -2.62 mm、8.78 mm 是预测帧检查值,未完整描述失败求解返回状态。回流类别修正已显著改变两段结果,因此应先修实现并重新定位,再决定是否需要跟踪、锚点或接近策略。

### 4.3 sub10 认证归零属实,单一原因尚未证明

独立重验 v3 与 v4 的 sub10 均通过 strict 终检,认证区间由每侧一个变为每侧零个。全段左右手满足箱体系低速门的帧数从 **14/15 降至 4/7**,不足以形成原有持续区间。仅修正 pair 类别也没有恢复认证。

当前 keep 使用物理距离覆盖,认证覆盖只是报告项,因此高接触覆盖和零认证可以同时出现。独立终检通过不等于持续抓握已得到充分验证。

箱体系运动增大是观测事实,但阶段 1/2 未做单项轨迹消融,又存在类别错误,不能把退化单独归因于“移除中间态走廊上界”。后续需分别检查跟踪目标、锚点和手部运动的冲突。

## 5. 建议执行顺序与阶段门

1. 补齐阶段 0/1:分离几何类别与行标签;统一所有成功返回检查;统计所有尝试及失败帧;分别记录预测检查、求解返回、回溯和最终拒绝原因;使 verbose 仅记录已有检查结果。
2. 增加针对真实回流链、best 状态失效和日志开关一致性的回归测试,重跑完整测试及六段 strict。共享修复逻辑还需重测标准模式。
3. 在新基线上定位 sub3 后续失败及 sub12 跟踪行为,记录原始预测、前帧接受状态、各求解候选和违规约束,不沿用失效归因。
4. 对仍存在的 sub12/sub16 路径碰撞,评估探测点约束或短窗口联合修复。探测约束须保留插值比例及场景信息,对插值状态相对端点增量的雅可比做有限差分验证,不能只加端点 pair。
5. 单独分析接触稳定性,报告每侧物理覆盖、认证覆盖、箱体系速度和锚漂。不得靠零认证下的空检查通过来宣称持续抓握可用。
6. 六段至少 4/6 保留,原保留段继续通过且质量差异有明确结论后,再进入 24 段。strict 容差、原始分母及数据划分约定保持不变。
