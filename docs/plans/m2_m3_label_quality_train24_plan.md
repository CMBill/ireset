## 1. 在整体方案中的位置

本工作属于主方案 [§9.1 教师数据与监督训练及 M3 教师清洗待办](interaction_retarget_impl_plan.md),承担 M3 收尾中的教师数据质量准入与小规模验证。对应[收尾方案](m2_m3_completion_plan.md)阶段 4 的标签适用性与转段判断,以及阶段 5 的 train24 数据验证部分;不覆盖阶段 5 中全部 M2 收尾工作。

```text
M0/M1:资产、配对、运动学与独立验收
    -> M2 修复器机制与正确性补修
    -> 本方案:六段质量重判 -> 标签分级 -> train24 受限验证
    -> 阶段 6:312 originals 教师重生成
    -> 阶段 7:M3 干净数据重训
    -> M4:闭环比较与最终评测
```

本轮回答现有教师能提供多少可靠的动作、几何与局部认证监督,并给出是否值得扩大数据生产的证据。轨迹通过 strict 并被 keep,不代表整段都具有可用的抓握监督。

### 1.1 已确认的推进选择

- 范围到六段质量重判及冻结 train24 验证;312 全量生成与重训列为条件性后续工作。
- 采用分级标签:合格轨迹可用于动作/FK 几何监督,接触辅助监督仅使用认证与参考接触区间的交集。
- 允许按本方案的受限门进入 train24;旧六段质量门继续单独报告为未通过,不追认旧门通过。
- 本轮修订的是允许开展何种数据验证及标签用途,不修改 strict 或 keep 标准,也不把持续抓握质量认定为已完成。

### 1.2 固定条件与边界

- 固定 G1 29-DoF 资产、原始输入、箱体轨迹、fps、分组、strict 阈值及插值协议;沿用现有独立终检的检查范围。
- 冻结求解器行为,稳定权重保持 **0**,任务工作门保持 **0.40 m**。不调整跟踪权重、预算、迭代数、速度边界或筛选规则。
- keep 规则不变:每个参考抓握帧数 >=10 的适用手侧,几何接近覆盖 >=50%;没有适用手侧仍不保留。
- 本轮不传入当前值为 0.113 的任务门 YAML,不重标任务门,不实施 sub7 数值边界修复、不新增求解策略、不执行模型训练或 M2 性能优化。
- 源数据、旧报告和旧实验目录保持只读;新产物进入独立版本目录。不替换困难样本、不裁短失败轨迹、不混用不同权重的成功结果。
- M2 扰动恢复率 >=95%、不可达零误受和 <50ms/帧,以及 M4 最终验收,继续作为独立工作项。

## 2. 阶段 A:订正证据并冻结质量协议

### 2.1 只读核查得到的基线订正

统一版本 Nq/Nv 为 **5/6 keep**,Ns 标准模式为 **6/6 accepted**。但方案设计期间核对完整质量表,并使用现有 `segment_quality_report.py` 对 Nq/sub10 产物独立复算,确认当前基线有以下三项质量退化:

| 指标 | v3 | 最新 Nq/Nv | 判定 |
|---|---|---|---|
| sub10 左手认证与参考区间交集 | 3 帧 | **0 帧**,认证总数为 3 | 原认证底线未通过 |
| sub10 右手几何接近覆盖 | 67/74 | 63/74 | 下降约 5.4pp |
| sub8 右手几何接近覆盖 | 79/80 | 78/80 | 下降 1.25pp |

质量表来源为 `derived/data/teachers_regenerated/quality_tables/six_segment_comparison_reviewfix_20260924.json`;sub10 复算产物位于 `reviewfix_20260923_nq_strict_task040/sub10_largebox_000.npz`。认证总帧数不能替代 `certified_in_ref_frames`。因此,旧记录中的“认证交集全达标”“仅两项偏差”需要订正。

sub7 的只读内存重放中,两轮独立终检均发现第 101 帧、关节索引 26(29 维关节数组零基索引)的速度为 **12.000000401362618 rad/s**,相对 12 rad/s 上限超出约 **4.0136e-7 rad/s**。对应帧级违反度约 **3.3447e-8**,低于当前帧级接受容差 1e-6,但严格终检仍拒绝。这支持帧级可行性容差与严格终检边界不一致的定位,不足以归因为原始动作存在不可恢复的快步。本轮保留拒绝,边界对齐另列修复。

上述 sub7 数字在方案设计时仅打印核查,未新增持久化诊断产物。实施阶段须补齐正式可复现证据,不能将本文件当作已经完成的诊断导出。

## 3. 阶段 B:落实分级标签与消费接口

### 3.1 标签用途

| 标签用途 | 准入条件 | 使用限制 |
|---|---|---|
| 动作与 FK 几何监督 | 完整轨迹通过 strict、任务工作门及 keep | 可用于状态重建、根旋转、FK 和一般速度监督 |
| 手部几何接近标记 | 合格轨迹中,参考接触且真实 hull 距离小于进入阈值 | 标记近接事实,不推导持续抓握或三 site 均贴面 |
| 局部认证监督 | 合格轨迹中,机器人认证区间与参考接触区间的交集 | 接触辅助损失仅使用这些帧;不宣称承重抓握 |
| 拒绝轨迹 | 任一准入条件失败 | 仅保留诊断,不进入训练数据清单 |

新增零认证侧仍可随合格轨迹参与动作/FK 监督,但其接触监督掩码必须为零。几何接近标记不能替代认证掩码。

### 3.2 数据产物与接口

- [ ] 导出每个 demo 一行的质量清单,包含状态、分组、输入/输出/资产/配置/协议哈希、帧数、fps、失败证据、标签资格和成本。24 个 demo 均保留记录,失败指标使用明确缺失原因。
- [ ] 合格轨迹附带轻量 NPZ:`hand_proximity_mask[T,2]`、`hand_contact_supervision_mask[T,2]` 及认证交集区间 ID,左右顺序固定。掩码为布尔值,无区间使用 -1;交集按连续片段编号并保留原认证区间边界。
- [ ] 区间使用半开边界 `[start,end)`。跨参考缺口、跨认证区间不能组成抓握时序样本;后续需要相邻帧掩码时,仅在两帧均有效且区间 ID 相同时成立。一般动作速度监督不使用该抓握限制。
- [ ] `TeacherWindowDataset` 增加可选质量清单入口,按原分组读取明确列出的轨迹及掩码,核验哈希、T、fps 与协议版本,保持 60/30 切窗。新入口不得静默裁剪认证过的标签或回退到原教师文件;检测到需要修改标签时显式拒绝加载。
- [ ] 参考人体与源/目标箱体轨迹的来源必须明确,并与认证产物绑定。模型输入 `batch["contact"]` 继续来自参考人体;新增监督掩码仅供损失使用,不进入 conditioner,也不参与推理条件构造。
- [ ] 旧数据入口保持历史行为;新入口缺失掩码、协议不匹配、分组或哈希不符时直接报错,不静默退回旧接触监督口径。

### 3.3 损失接入

- [ ] 在现有 `LossAssembler` 的接触损失入口,为分级数据使用 `hand_contact_supervision_mask`,按有效帧归一化;空掩码贡献零损失、零接触梯度。
- [ ] 动作/FK/一般速度损失仍使用完整合格窗口,不因抓握认证稀疏而误屏蔽其余动作标签。

- [ ] 完成新清单到窗口、条件编码、损失的前向/反向冒烟验证,不执行训练步骤、不更新模型权重或检查点。

## 4. 阶段 C:六段回归与 train24 实验

### 4.1 执行顺序

1. **冻结版本。** 标签工具、证据报告和接口测试通过后冻结代码、有效配置、依赖及资产哈希。新诊断和产物使用独立目录,不覆盖历史结果。
2. **六段回归。** 同版本执行 regen quiet、regen verbose、standard 各一次。预期保持 regen 5/6、standard 6/6;逐段状态、尝试计数和轨迹数组须与冻结基线一致,耗时单列。出现行为差异先定位,不进入 24 段。
3. **受限转段。** 六段数量门 >=4/6、sub10/sub8 保留、全部保留轨迹 strict 通过,且掩码及报告契约成立,才启动 train24。旧认证/覆盖回归门继续标未通过,sub10 左手接触监督必须为零。
4. **完整运行。** 使用已冻结的 `calibration24_train_v1`,核对 24 个唯一 train demo、与 val/test 零交集、输入哈希及清单哈希;执行完整轨迹,不按本轮结果替换样本。
5. **固定运行条件。** 单进程串行、`OMP_NUM_THREADS=8`,记录其余线程环境、机器负载、磁盘可用量与完整 argv;使用 `uv run --locked`,不传任务门 YAML,启动时断言有效任务门为 0.40。
6. **完整分析。** 报告求解成功、strict 通过、keep 和窗口可用数量;统计受试者分布、时长、参考接触阶段、箱体平移/旋转及人体运动范围,对比保留与拒绝集。单列已反复诊断的 6 段与其余 18 段,不把总体结果当作独立泛化证据。
7. **冻结裁决。** 按下节预注册规则形成转段建议。失败项完整保留,不通过事后重标工作门或挑选实验变体取得通过结论。

清单位置:`derived/data/screening/calibration24_train_v1.json`;清单内冻结哈希为 `52a98507fe0ea601fffeba768fa66edf0ac936217c7f2dec6a81001a28b9ad96`。保留旧混合集和历史测试暴露记录,不改变原 test 分母。

### 4.2 预注册裁决与停止条件

| 项目 | 要求与处理 |
|---|---|
| 正确性与产物契约 | 所有保留轨迹通过独立 strict;清单/掩码/源数据一致;任何错误先阻止后续扩展 |
| 数量门 | 至少 **18/24 keep**;分母始终为冻结的 24 段 |
| 动作覆盖最低检查 | 六个受试者均有可用 60 帧窗口,并报告各阶段及运动范围的保留偏差;非零覆盖不等于训练数据已经充足 |
| 动作/FK 扩展建议 | 数量门、动作覆盖最低检查及产物契约同时满足,才建议另行开展扩大生产 |
| 局部认证用途 | 单独报告逐侧认证交集帧、连续时长、双手重叠和零认证样本;可用帧仅按掩码消费 |
| 持续抓握就绪 | 保持独立未完成状态,不得由数量门或局部认证帧推导通过 |
| 未达标 | 停止规模扩展,按失败类别另立最小修复方案;不扩大分母外候选池补足成功数 |
