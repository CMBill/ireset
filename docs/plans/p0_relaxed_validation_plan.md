# P0 阻塞项解决方案(2026-09-13 修订版):分层干预建立教师基准

应对 M2/M3 双重证实的教师轨迹整段修复接受率 0% 阻塞问题。本版取代同日第一稿:第一稿提议"临时放宽验收容差",经代码审阅与探针实验证实**放宽层选错**(详见 §1.1),且多数放宽数值依据有误;本版改为"先语义解耦、后阈值放宽、每步以失败分类学为决策依据"的分层方案。第一稿的 Three-stage 结构(基准 → 标定 → 闭环)保留。

## 1. 问题诊断(修订:以 2026-09-13 探针证据为准)

### 1.1 层错位:放宽最终验收器对 `rejected_frame` 是空操作

`rejected_frame` 产生于顺序循环内部(`src/ireset/repair/pipeline.py:220-250`):每帧先过 `frame_valid()`(阈值来自 **RepairConfig**,即 `configs/repair/qp_default.yaml`),失败进 SCP 求解器,不可行才拒绝;`IndependentValidator`(ValidationConfig)只在**全部帧接受后**运行(`pipeline.py:179`)。M2/M3 的全部失败都是 `rejected_frame`,管线从未到达最终验收。

**探针证据**(教师段 `sub10_largebox_000`,120 帧):严格配置 t_fail=59、`skip_reason=state_constraints`、求解器 `infeasible`、前缀 54/59 帧靠 slack 回退;**仅把 ValidationConfig 换成第一稿的放宽值(其余不动),失败逐位相同**(同 t_fail=59、同状态)。结论:P0 的干预点必须在修复侧(`qp_default.yaml`)+ 验证侧成对出现,任何只动 `protocol.yaml` 的方案无效。

### 1.2 失败机制链(单段完整解剖,sub10_largebox_000)

1. 第 ~5 帧左脚进入参考支撑区间,G1 脚底间隙落在建立带内 → **世界系脚锚点锁定**;
2. 教师的 G1 输出在支撑期**滑动 ~0.3 m/s**(M1 已量化;注意参考人脚本身是准静态的——见 §1.4,滑动是重定向输出的问题),而锚定后 `foot_speed` 行限 ±0.7mm/帧、锚带 ±1cm;
3. 修复被迫钉住脚、其余部位跟随参考 → 修复态逐帧偏离预测(根位移差 1cm@t=6 → 14.9cm@t=30 → 22cm@t=58);
4. 偏离使 z_pred(t) − z_accepted(t−1) 超出单帧速度预算(根 0.219m/帧 ≈ 6.6 m/s vs 限 1.8),slack 回退也无法在任务门槛 0.40 内调和 → `task_quality` 拒绝。

### 1.3 教师不可行分类学(探针实测,写 P0.0 工具将其系统化)

| # | 绑定约束(修复侧 QP 行) | 机制 | 探针证据 |
|---|---|---|---|
| 1 | `foot_speed` / `foot_anchor`(锁锚后冻结) | 支撑期滑动 vs ±0.7mm/帧 + ±1cm 锚带;累计漂移最终耗尽速度行/任务预算 | t=6/7/30 违反 3–61×;t_fail=59 |
| 2 | 非接触 +2mm 间隙(未锚的贴地脚) | 接触带分类跟**锁定锚点**走(`scp.py:258-273` 查 `ctx.foot_anchor is not None`),未锚的贴地脚被要求离地 2mm | 锚点建立加速度门后 t=12 即死 |
| 3 | 支撑带上限 5mm(参考支撑期脚悬浮) | 教师脚在参考支撑期离地 6–9mm,带上限强制贴地 → 下压 → 漂移/不可行 | sub12 t=0;sub10 t=45 |
| 4 | 手部带/锚(参考抓取期手漂移) | 教师手在抓取期离箱面 2–2.7cm 或漂移,≤1cm 带上限 + ±1cm 锚带违反 | sub3 t=4,违反 8.4× |
| 5 | 速度跳变(数据伪影) | 帧间根 5.29 m/s / 关节 22.29 rad/s 跳变,任何预算外 | 20/312 original 文件(6%) |
| 6 | 任务预算耗尽 | 漂移累计后 task_mpjpe > 0.40,#1–#4 的共同终态 | t_fail=59 slack 路径 |

关键结构性发现:**架构缺少"触地但未锚定"状态**——滑动的贴地脚在当前设计下两头堵(锁锚必须冻结、不锁必须离地)。这是语义缺口,不是容差问题。

### 1.4 参考侧与数据侧的量化事实

- **参考人脚在支撑区间内是准静态的**:6 个受试者各取 1 个 original(687 帧),支撑帧内速度中位 0.028 m/s、p90 0.127;87% 帧 <0.10 m/s;仅 5/26 区间是持续滑移(p90 ≥0.20)。因此把参考侧推断门 `ref_foot_speed_mps` 从 0.35 降到 0.10/0.05 **不改变**失败(探针:t_fail 仍 59)——第一稿"参考侧已用 0.35"的引用本身也是类别混淆:那是推断门(速度快于它的脚不算接触),不是任何验收容差的先例。
- **教师输出速度基本在限内**:312 个 original 的帧内根速度 max 的中位 0.83 m/s、p90 1.39(限 1.8);关节 max 的中位 5.87、p90 8.94 rad/s(限 12)。**6%(20/312)文件含超限跳变**(first-spike 中位帧 60;mod-60 ∈ {0,1,59} 占 30%,弱窗口边界聚类)。
- 第一稿"教师手漂移 ~2.4cm"来源系误读:protocol.yaml:51 记录的是 hover-inclusive 区间上 **~2.4 m**。本探针在抓取期实测手-箱面距离 2–2.7cm(sub3),后续定值以此类重测为准。
- 第一稿"连锁影响"中"首帧必修→连环失败"与实测不符(各段 t_fail ∈ {0,4,45,59});真实机制是 §1.2 的中段累计漂移。

### 1.5 连锁影响(保留)

- 质量门槛(`task_mpjpe_tol_m`,当前 0.40 工作值)无法在验证集标定(方案 §8.4 要求);
- §10.1 的 ≥90% 整段接受率对**一切输入**不可达(教师噪声基线同拒,M3 已证);
- M4 闭环评测前置条件未满足。

## 2. 总体策略

原则:**语义修正在前、阈值放宽在后;每一层的介入都由失败分类学触发、以登记集上的测量验收;放宽永不触碰碰撞/限位;所有放宽结果明确标注为非 §10.1 达标**。

- 语义修正 = 恢复缺失的状态/解耦错误的耦合(不改变任何 §10.1 容差的数值);
- 阈值放宽 = 仅在分类学证明某行族持续绑定且语义修正无效后进行,修复侧与验证侧成对修改并保持"修复带 ≤ 验收门"不变式(当前只在注释中,改为加载时代码强制);
- 分类学 #5(跳变伪影)走数据筛查,不属于放宽范畴。

## 3. P0.0 失败分类工具与登记输入集(新增,先于一切干预)

1. **登记输入集**:6 个受试者各取首个 original(与 M2 P1 相同的 6 段)为诊断集;标定集扩至 M1 基线的 24 个 original(P0.2 用)。排除 §1.4 的 20 个跳变文件(预注册数据质量筛查,记录排除原因与清单,不从分母静默消失)。
2. **行级诊断工具**:扩展 `scripts/eval_repair.py`(或新增 `scripts/diagnose_repair.py`),对每个被拒段输出:t_fail、skip_reason、求解器 status、失败帧预测点违反行的**类别计数**(joint_vel / base_vel / noncontact_clearance / contact_band(脚/手) / foot_speed / foot_anchor / hand_anchor / task)、失败帧 pred-z_prev 位移差、slack 帧占比、前缀 frame_status 串。本修订的探针逻辑(对 `solve_frame` 的捕获 + accept 模式行评估)即为原型,入库为可复现脚本。
3. **验收**:6 段诊断集全部产出分类学行;分类结果与本文件 §1.3 一致(不一致则先更新本文件再继续)。

## 4. P0.1 分层干预(修订:替换第一稿的"放宽 ValidationConfig")

按阶梯执行,每层跑完登记集测量后再决定是否进入下一层;**到达目标即停**。

### L0 非语义修正(不动任何阈值语义)

- SCP 迭代预算 15+15 → 40+40(失败多为 15 迭代内 merit 不收敛的 `infeasible`);
- 多起点重启(从 z_prev 与 z_pred 双起点取优;M2 收尾清单第 1 项,提前至此,两处共用同一实现)。
- **验收**:诊断集接受率或 t_fail 分布改善 ≥1 段;否则记录后进入 L1。

### L1 语义解耦(§10.1 容差数值全部不动)

探针已验证方向(V3 系列,单段证据):

1. **脚部接触带改由参考调度驱动**:`scp.py:_foot_hold_overlap` 从"锚点已锁"改为"参考 wants 支撑"(手部**保持**锚点驱动——探针中把手的带也改成参考驱动会导致悬停手被 ≤1cm 带上限强制拉近,t_fail 反而前移);
2. **锚点建立加准静态门**:脚速 ≥0.05 m/s 不锁锚(滑动支撑 = 触地但不冻结,与"触地状态验证通过后才能锁定脚锚点"约定一致);
3. **验证器机器人侧推断门对齐**:`foot_entry_speed_mps` 0.3 → 0.05(支撑 := 准静态;滑动贴地段视为过渡,不做支撑检查——语义上不再认证,而非放宽认证)。
- **验收**:诊断集逐段重跑分类学;#1/#2 类失败消失。探针当前进展:sub10 t_fail 59→45、sub12 t=0、sub3 t=4,剩余绑定转為 #3(支撑期悬浮 6–9mm)与 #4(手部漂移 2–2.7cm)——即 L1 不足以单独达标,预期内。

### L2 交互模型阈值放宽(成对、最小、逐项记录)

仅对分类学证明持续绑定的行族放宽;每项 = 修复侧字段 + 验证侧字段成对,且过不变式检查:

| 行族 | 修复侧(qp_default.yaml) | 验证侧(protocol.yaml) | 不变式 |
|---|---|---|---|
| #3 支撑悬浮 | `foot_contact_band` 上限 0.005 → 实测 p90 + 2mm 裕量(≈0.010) | `foot_ground_gap_m` 0.005 → 同值 | `foot_enter_m(0.005) ≤ foot_ground_gap_m` 与修复带 ≤ 验收门 |
| #4 手部悬停/漂移 | `contact_band_gap_m` 0.01 → 实测 p90 + 裕量(探针 2–2.7cm → ≈0.035);`hand_anchor_tol_m` 同比 | `hand_gap_m`、`hand_anchor_error_m` 0.01 → 同值 | `hand_enter_m(0.01) ≤ hand_gap_m` |
| #1 残余(若 L1 后仍有锚定带绑定) | `foot_anchor_tol_m` 按锚定段实测漂移分布定 | `foot_anchor_drift_m` 同值 | 修复带 ≤ 验收门 |

碰撞(±2mm)、关节/根限位、关节/根速度界**不放宽**。每项放宽在 yaml 注释记录:原值、新值、依据(分布统计 + 日期)、失效条件(M2 收尾或路径 B/C 完成后收紧)。

- **验收**:诊断集整段接受率 **≥50%**,或在**截断前缀基**(沿用 M2 P1b:取被拒段接受前缀重修)上 ≥70% 且记录截断分布;同时报告逐检查通过率与 slack 帧占比(接受段 slack 占比 >50% 时须在结论中显式标注"基准以 slack 修复为主")。两者都不达 → 停止阶梯,转路径 B(§7),不再追加放宽。

### 代码与配置改动清单

- `ValidationConfig` 增加 `from_mode(mode)` / `RepairConfig` 增加 `validation_mode`,但 **mode 同时驱动两份配置**(第一稿只接验收器,已证无效);`RepairPipeline.__init__`(`pipeline.py:58`)当前以默认值构造验收器,需把 cfg 传入;
- 两份配置加载时强制不变式:修复带 ≤ 对应验收门、enter ≤ gate(后者已存在于 `validation.py:63-69`,前者新增);
- 所有放宽产物 JSON 内嵌 `mode` 字段,文件名带 `_relaxed` 后缀,防止与严格结果混算。

## 5. P0.2 任务质量门槛标定(修订)

第一稿引用的 `pipeline.py::task_quality_valid()` **不存在**;任务门槛已内联于 `frame_valid`(`pipeline.py:158-159`,`res["mpjpe"] > task_mpjpe_tol_m`)且全模式常开。本阶段是**标定现有门槛**,不是新增检查;"严格模式下跳过"会移除现有检查,禁止。

1. 标定对象仅 `task_mpjpe_tol_m` 一个门槛(0.40 工作值)。laplacian E_L 与接触 F1 按 §10.1 属**报告项**不是门槛(第一稿的 `task_contact_f1_min` 硬门删除:F1 是整轨迹指标,顺序管线无法逐帧评估,且修复器接触行为按构造跟随参考调度,门控自参照);
2. 输入:P0.1 接受段(含前缀基)上计算修复诱导偏差分布,`mpjpe_tol = p95 + 0.02`;标定集 ≥24 个 original、跨全部 6 受试者;锁值注释注明"在放宽模式接受集上标定,带自选择偏置";
3. `scripts/calibrate_task_gates.py` 新增实现(第一稿清单保留此项);
4. **验收**:带标定门槛重跑 P0.1,接受率下降 <10 个百分点;超限则放宽裕量重标一次,仍超则保持 0.40 并记录(说明分布重尾)。

## 6. P0.3 生成-修复闭环验证(修订)

1. **CLI 与实际对齐**(第一稿命令含不存在旗标):`eval_repair.py` 现有 `--per-subject/--frames/--bases-only`,需新增 `--validation-mode/--output`;`eval_generation.py` 现有 `--models/--demos/--frames/--ddim-steps/--seed/--models-dir/--skip-baselines`,需新增 `--validation-mode`(基线 σ 固定 0.02/0.05,第一稿的 `--baselines/--include_repair_pipeline` 删除;修复在 eval_generation 中本就默认执行);
2. 教师(无噪声)基线**复用 P0.1 产物**,不在 eval_generation 重跑;
3. 指标与验收条件改用 §10.1 既有公式,不发明模糊比较:
   - 整段接受率(分母 = 预登记全部输入;分子 = 独立终检通过);
   - **MPJPE ≤ 教师基线 + 2cm**(共同成功样本配对,列明样本数);
   - **手接触 F1 ≥ 0.95 × 教师基线**(全测试集按演示宏平均的成功加权值,拒绝记 0);
   - 失败分类(筛查拒绝 / 修复不可行 / 质量不达标)+ **slack 修复帧占比** + 修复幅度(根平移/旋转、关节 RMS/max 分开报);
   - 计时:生成 + 修复端到端,均值/p50/p95/max,拒绝案例也计时;
4. **验收**:生成接受率 ≥ 教师基线接受率,且上述两项质量条件满足;报告首页标注"**临时放宽容差 + 语义修正模式,非 §10.1 达标;严格约束验证推迟至 M2 收尾/路径 B/C**"。

## 7. 后续收敛路径

**路径 A(M2 收尾优先)**:完成扰动接受率 60%→95%、单帧 310ms→<50ms 后,收紧回严格容差重跑 P0.3。预期写保守:探针表明教师失败是交互模型级(分类学 #1–#4),M2 收尾清单(多起点、两段收紧、持久工作区)主要救**扰动恢复**,对教师持续滑移/悬浮/手漂移不构成解;"优化后可能双双通过严格验收"不作为预期,只作为待验证假设。

**路径 B(教师重生成,高成本,§1.3 分类学的彻底解)**:用带交互模型约束的修复器/优化器重生成教师轨迹,筛选通过严格验收的作为新教师;重训生成模型。分类学证据(教师输出系统性违反支撑/抓取模型四个行族)指向该路径大概率不可绕过。

**路径 C(新增:语义修正固化)**:L1 的三项解耦(参考驱动脚部带、准静态锚定、推断门对齐)本身是正确的模型修正且**不触碰任何 §10.1 容差**;无论走 A/B,都应固化为正式实现 + 测试(探针级证据需转为带回归测试的代码)。注意:验证器推断门 0.3→0.05 与参考侧 `ref_foot_speed_mps` 语义对齐后,若同步改参考侧会影响 M3 条件输入(接触调度)→ cache 重算与重训,波及面大,单独评估后再动。

## 8. 技术决策记录(修订)

| 决策 | 理由 |
|---|---|
| 放弃"仅放宽最终验收器" | 探针证明对 `rejected_frame` 逐位无效(§1.1);失败全部在修复侧 QP 行 |
| 语义解耦优先于阈值放宽 | "触地但未锚定"状态缺失是结构缺口(§1.3 #2);L1 不改变任何 §10.1 容差 |
| 脚/手接触带分类区别对待 | 探针:脚改参考驱动前进(t_fail 59→45),手改参考驱动后退(悬停手被带上限强制拉近) |
| 碰撞/限位/速度界不放宽 | 硬约束;速度界已按教师分布标定,放宽即失去 §10.1 意义 |
| `foot_entry_speed_mps` 0.3→0.05 属语义修正 | 支撑 := 准静态;滑动贴地视为过渡、不认证,而非放宽认证标准 |
| 每项阈值放宽成对出现并代码强制不变式 | "修复带 ≤ 验收门"目前只在注释;两份配置须同步否则无效或自相矛盾 |
| 跳变文件走数据筛查而非放宽 | 6% 文件含 5.29 m/s / 22.29 rad/s 帧间跳变,任何预算外;预注册排除并记录 |
| task gate 只标定 `task_mpjpe_tol_m` | 门槛已存在且常开;E_L/F1 按 §10.1 是报告项;F1 无法逐帧评估 |
| P0.3 质量条件采用 §10.1 公式 | 第一稿"质量 ≥ 基线 95%"未定义配对与分母,按字面不可满足 |
| 产物内嵌 mode 字段 | 防止放宽结果与严格结果混算 §10.1 |
