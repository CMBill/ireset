## 1. 目标与边界

- 修复目标只有三个,与失败类别一一对应,每类先取证(D 阶段)后修复:
  - **V 类**(终检速度微超限,3 段):帧级接受与严格终检的速度边界对齐;
  - **F 类**(regen 手带/接触带行贴穿透下界的帧级不可行,5 段确认 + 1 段待归因):帧级验收判定改用验收级穿透下界;
  - **R 类**(sub10 系接触召回不足,2 段):regen 模式下 skip 门与走廊目标脱节的结构修复。
- **冻结值全部不变**:关节速度上限 12 rad/s、根线 1.8 m/s、根角 7 rad/s;穿透容差 −2 mm;任务工作门 0.40 m;keep 判据(每适用侧几何接近召回 ≥0.5、参考抓取帧 ≥10);strict 模式;标签协议 `graded_labels_v1`;train24 清单 `calibration24_train_v1`(哈希 `52a98507…`)与 31 test 分母。
- 求解器驱动界(QP 行)与探测行(插值态)语义不变:QP 带行下界仍 −1.5 mm(regen)、探测行仍按 `band_margin_m=0`(−2 mm)。本方案只动**帧级验收判定**与**状态采纳点**,不动任何驱动行、权重、行预算、迭代数、信赖域。
- 不新增依赖;不动 `resources/`;历史产物目录只读,新产物写入 `derived/data/teachers_regenerated/train24fix_20260927_*`。
- 数量门重跑后仍以 **≥18/24 keep** 裁决;未达标则停止,以新证据另立下一轮方案,不在本轮内迭代修复或扩大候选池。

## 2. 失败证据与机理定位

以下数值取自 `labelq_20260926_train24/regen_final/regen_report_calibration24_train_v1_strict.json` 与 `train24_analysis_final.json` 的逐段结构化证据(2026-09-26 洁净运行),机理均已在当前代码中定位到函数与常数。D 阶段(§3)先以 verbose 重放固化为正式取证,再实施修复。

### 2.1 V 类:终检速度微超限(3 段,`rejected_final`)

| 段 | 差分帧 | 关节(零基) | 值(rad/s) | 超限量 |
|---|---|---|---|---|
| sub7_largebox_000 | [100,101] | 26 | 12.000000401362618 | 4.0136e-7 |
| sub12_largebox_077 | [202,203] | 16 | 12.000000105688033 | 1.0569e-7 |
| sub8_largebox_048 | [11,12] | 26 | 12.000000003086466 | 3.0865e-9 |

均为 joint 族;三段都是 slack 重度段(slack 尝试 86/69/162,总尝试 119/81/206)。后缀重试(自帧 96/198/7 起)重放出**逐位相同**的超限值——失败由确定性的 QP 解本身产生,不是教师输入或随机性。

机理(代码锚点):

1. 关节速度行(`scp.py::_fixed_pre_rows` 行 [29:58))是**精确线性行**:`val = q + dq − q_prev`,界 `±dt·12 = ±0.4 rad`。OSQP 以 `eps_abs=3e-5, eps_rel=3e-5, polish=False` 求解(`scp.py::solve_qp`),允许行残差到 ~4.2e-5 rad;slack/restoration 模式下行惩罚有限,最优点骑在界上并以边际量越过。
2. 帧级可行性判定(`scp.py::solve_frame`:`viol = violation(val,lo,hi,scl) ≤ 1e-6`)对该行的归一化违反度为 `3.3e-8 ≤ 1e-6` → 帧被接受(验证记录 §2 已记录该定位)。
3. 独立终检(`validation.py::_check_velocities`)用严格比较:`|diff|/dt > 12.0` 即拒。帧级 1e-6 归一化容差(≈1.3e-8 rad 余量)与严格终检边界不一致。

机理(代码锚点):regen 模式带行(手 regen 行 + 脚接触带行)的下界在 `scp.py::_collision_rows`(约 979-981 行)为 `−contact_band_pen_m + 0.0005 = −0.0015 m`,**与 mode 无关**——`constraint_rows(mode="accept")` 的 docstring 声称"accept 使用验收级界(处处容忍到 −2 mm)",但 `_collision_block(mode="accept")` 只把上界无穷的非接触行放宽到 `cfg_noncontact = −0.0018`,接触带/regen 行保留 −0.0015。于是:

- QP 驱动解骑在 −1.5 mm 行界上(带行解按构造骑界,注释自述);OSQP 行残差 ≤3e-5 m 允许微米级越界;
- 帧级验收 `violation ≤ 1e-6` 以 `penetration_scale_m = 0.002` 归一化,只容忍 **2e-9 m** 越界——对 QP 自身只能做到 ~30 µm 的行要求纳米精度;
- 而独立终检的穿透门是 −2 mm:−1.52 mm 完全通过。**帧在验收级可行,却被求解级的探测保护裕量判死。**

`sub16_012`(−3.98 mm)连验收级 −2 mm 也超出,是真实不可行,不属本类,预期修复后仍拒绝(§3 D-F 重新归因)。

## 4. 修复设计

三项修复相互独立、分别提交;每项附带能把原失败机理构造为反例的测试。所有修复不动 §1 冻结值。

### 4.1 V1:采纳点速度投影 + 帧级严格判定

- [ ] 新增采纳点投影:对每个将被写入输出轨迹的候选状态 z(skip 采纳的原始预测、求解/回退采纳的候选,含后缀重试重解路径),若 `ctx.z_prev` 存在,按关节逐维裁剪 `z[7:36]` 到 `[q_prev − dt·12, q_prev + dt·12]`。投影发生在**任何接受检查之前**,保证被检查的状态 == 被采纳的状态;`z_prev` 取上一个已采纳(已投影)状态,与终检 diff 口径一致。帧 0(z_prev=None)不投影。
- [ ] 投影事件计数进 frame_log 与成本视图(触发帧数、最大裁剪量 rad);幅度上界为 OSQP 行残差 ~4.2e-5 rad(远小于既有关节限位裁剪容差 1e-3 rad 的先例),不修改根平移/旋转。
- [ ] 帧级判定收紧:投影后,速度行 [29:58) 的帧级可行性以**零容差**(浮点守卫 1e-12 rad)参与判定——投影使线性行可精确满足,1e-6 归一化容差不再适用于该块;根线/根角**范数行不变**(无可分离投影、无观测失败,残留风险如实记录)。
- [ ] 六段标准模式 Ns 预期**字节不变**:其已采纳链通过了严格终检 ⇒ 每次采纳点速度差分 ≤12·dt 精确成立 ⇒ 投影恒为无操作。回归中逐段核对,不符则如实报告并停在该步。

回归测试:(i) 以 sub7 实测值 12.000000401362618 rad/s 构造 `q_prev/cand` 对,投影后差分/dt **逐位** ≤12.0、frame_log 记录裁剪;(ii) 投影幂等、无违反时零改动、根分量不动;(iii) skip 采纳路径同样被投影(D-V 若确认需要,否则至少测试钩子在位);(iv) 帧级严格判定:构造线性行 eps 级越界且未投影的状态 → 帧拒绝(反例锁死回归);(v) 范数行行为不变。

### 4.2 F1:验收级带行下界

- [ ] `_collision_rows` 的带行下界在 **accept 模式**改为 `cfg_noncontact(cfg) = −0.0018 m`(与既有非接触行验收级常数统一:验收门 −2 mm + 0.2 mm 探测裕量),仅当 `band_margin_m is None 且 mode="accept"` 时生效;显式传入 `band_margin_m` 的调用(探测路径的 0 值)不变。**QP 驱动行(repair 模式)保持 −0.0015**,标准模式 accept 带行下界保持 −0.002(不动,避免标准基线漂移;现状内部不一致——带行 −2.0 mm vs 非接触行 −1.8 mm——如实记录为已知现状,不在本轮统一)。
- [ ] 影响面:`solve_frame` 帧级可行性判定与 `_frame_valid` 端点检查(均经 `constraint_rows/check_rows(mode="accept")`)、`success_review`。µm 级越界(≤30 µm < 0.3 mm 松动量)不再判死;−1.9 mm 及更深仍拒绝;探测行(−2 mm)与终检(−2 mm)不动,插值路径依旧受检。
- [ ] 预期状态链漂移:regen 六段中带行贴界的帧判定放宽,接受时机可能提前 → Nq/Nv 需重新冻结(§5);标准模式 Ns 不受影响(其带行下界本就 −0.002,改动仅在 regen 分支)。

回归测试:(i) regen 模式下,手带行值 −0.0016 的状态:帧级验收**可行**(修复前不可行),QP 行仍以 −0.0015 驱动,探测行仍 −0.002;(ii) 值 −0.0019:仍不可行;(iii) 标准模式 accept 带行下界逐位仍 −0.002;(iv) 修复前反例:−0.0016 在旧实现下归一化违反 2e-4 > 1e-6 被拒——用旧常数锁定行为差异;(v) 终检穿透门 −0.002 与 `penetration_scale_m` 不变。

### 4.3 R1/R2:regen 模式 skip 门与走廊选取(D-R 判定后实施)

- [ ] **R1(skip 门,预期主修复)**:regen 模式下,帧可 skip 的必要条件追加——对每个 `ref_hold` 为真的手侧,候选状态的最小手 geom/箱距离 ≤ `regen_hand_contact_gap_m`(0.008 m,该值本就为 < hand_enter 0.01 而设)。违反则强制求解(走廊行 + 跟踪目标随即参与)。标准模式 skip 门不变。接近帧(走廊闭合期)将必然求解,属预期成本(§6 计时如实汇总)。
- [ ] **R2(走廊选取,仅当 D-R 判定 (b) 成立)**:ref_hold 为真的侧,regen 行的最近手 geom/箱 pair 选取绕过激活边距候选门,直接从注册表全量手 geom(每侧 3 个)对箱查询最近者;上界走廊公式不变。选取仍逐线性化重跑。
- [ ] 两项均为**参与性修复**(让走廊机制真正作用于悬空段),不调权重、不调走廊速率、不调阈值——§7.2 教训(预注册权重对照为负)继续生效。
- [ ] 诚实风险预注册:R1 可能把"接受但无用"段转为 rejected_frame(走廊不可行类),数量门不因此放水;sub10_000 等已 keep 段的状态链可能漂移(更多求解帧),以六段回归核对认证交集不退化。

回归测试:(i) regen 模式、ref_hold 真、手距 0.03 m 的候选:skip 被拒、求解被调用、QP 含该侧 regen 行且上界符合走廊公式;(ii) 手距 0.006 m:skip 允许;(iii) 标准模式:门惰性(同样状态照常 skip);(iv) R2(若实施):手距 0.2 m 时最近 pair 仍被选取为 regen 行;(v) frame_log 记录 skip 拒绝原因(`corridor_gap`)。
