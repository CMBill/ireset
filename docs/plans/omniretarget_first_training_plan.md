# OmniRetarget 优先教师与初步训练执行方案

日期：2026-10-08。状态：**推进方向已由用户明确，本文件为执行方案；本次仅编写文档，尚未实施新接口、生成新教师或启动训练。**

本轮目标是先利用 OmniRetarget 教师获得可解释的学习与闭环基线，再根据实际瓶颈决定是否修复教师、补充数据或更换教师生成方法。初步训练不再以自研教师重生成的六段门或 train24 门通过为前置。

## 1. 决策与历史方案的关系

### 1.1 已确定的推进方向

1. 教师主来源为 OmniRetarget：优先复用已有发布轨迹；存在明确的数据缺口时，再用固定版本上游工具生成。复用发布轨迹属于本路线，不为启动训练重复生成已有标签。
2. 先完成配对和数值核查，以近似动作标签训练确定性预测器与条件扩散模型。
3. 自研修复器继续用于生成结果的检查与修复；独立验收器继续决定输出是否可接受。
4. 第一轮以动作生成能力为主，手部接触损失默认关闭；可靠接触监督作为后续有限增量实验。
5. 第一轮结果交付后，再判断教师缺陷是否已经成为主要瓶颈。本轮不启动全量自研重生成、R 候选追加搜索或其他教师方法开发。

### 1.2 对既有阶段门的影响

本方案新增一条独立的“OmniRetarget 动作监督训练”路线，采用独立的数据协议和运行目录。

- [train24fix3 收敛恢复方案](train24fix3_convergence_recovery_plan.md)及其[验证记录](../verification/train24fix3_convergence_recovery_verification.md)中的 D+ 终局保留：R1/R2/R3 分别为 1/6、1/6、2/6，winner=None。
- 自研严格教师生产路线的 train24、312 originals 重生成及其干净标签重训继续暂停；本方案不将其改记为通过。
- 新动作训练路线由本文件的数据、接口和数值正确性门驱动，允许使用存在已记录运动学缺陷的教师，不等待上述生产门。
- [graded_labels_v1](../../configs/labels/graded_labels_v1.yaml)继续适用于其原有严格教师用途；本方案不修改其准入含义，也不将失败轨迹伪装成该协议的合格标签。
- [主方案](interaction_retarget_impl_plan.md)的最终整段质量目标、接受率和加速要求继续有效。本轮是初步基线，不以训练完成代替最终达标。

新增训练协议不改变输出碰撞、限位、速度、脚支撑和手抓取验收阈值。

## 2. 已有证据与本轮要回答的问题

### 2.1 已有基础

以下为历史检查快照，正式执行时重新核对文件与哈希：

| 项目 | 已有事实 | 本轮用途 |
| --- | --- | --- |
| OmniRetarget 发布数据 | 1,826 个 NPZ、312 个原始演示、323,812 帧、30 Hz | 主要教师来源 |
| 轨迹字段 | qpos=[T,43]、human_joints=[T,52,3]、fps | 根位姿和 29 维关节监督 |
| 原始演示分组 | train/val/test=250/31/31 | 原分组保持，变体随父演示 |
| 含增强的训练库存 | 1,469 文件、258,462 帧、历史 6,431 个 60/30 窗口 | 后续增强实验的库存参考，不是 original-only 规模 |
| M0 配对核查 | 71 个样本的坐标、人体尺度和时间关系已有证据 | 复用映射方法，扩展到实际使用文件 |
| 历史 M3 pilot | 两模型已能输出完整状态；旧 4k 步实验未充分收敛 | 复用实现，不把旧实验当本轮完成 |
| CPU 工程优化 | 统一进程池、缓存和线程限制已验收 | 数据预处理与离线检查复用 |

### 2.2 核心问题

本轮按顺序回答：

1. 条件与标签是否真正对齐，模型是否能拟合小规模训练样本？
2. 在固定验证演示上，模型能否复现教师的全身动作和人与箱体的任务关系？
3. 教师、确定性预测和扩散预测进入同一标准修复器后，各自在哪里失败、需要多少修改和成本？
4. 主要瓶颈属于条件构造、模型拟合、教师缺陷、修复器，还是固定输入本身？

“教师有缺陷”不能单独推出“应替换教师”；“模型已拟合教师”也不能单独推出“输出可行”。

## 3. 教师来源、资产和数据范围

### 3.1 首轮使用范围

主实验先使用 `*_original.npz`，覆盖锁定分组中的全部原始候选演示；逐文件核查后形成实际可训练清单。首轮不引入 rot/trans 变体，降低增强语义和变体数量差异对诊断的干扰。

- 训练候选：原 train 的 250 个原始演示。
- 验证候选：原 val 的 31 个原始演示。
- 测试：保持原 test 的 31 个演示，本轮不用于模型或规则选择。
- 17 个没有公开教师的 PT 保持 reserve 身份，本轮不补生成、不直接加入 train。
- T<60 的轨迹不用于首轮训练窗口；短轨迹的独立演示和时长单列。评估中不得因为长度或失败静默缩小已冻结分母。

数据审计可以登记 test 的身份、格式与配对，不能据 test 的任务、接触或可行性指标调整训练和筛选策略。

### 3.2 来源和资产锁定

发布数据 revision 固定为 `135259130158f1cb1799e4ab9b6566c938285fc9`。记录下载归档、实际读取的 NPZ、配套发布模型、项目锁定 G1/箱体资产的完整 SHA-256。

项目目标资产继续使用普通手的 G1 29-DoF 锁定版本，不混入 spherehand。发布资产与项目资产分别登记，核查关节名称/顺序、关节轴、根坐标、mesh 缩放、箱体原点和手部碰撞代理。运动学一致性不足时先修正适配；格式、碰撞代理差异本身不自动触发完整教师重写。

源 OMOMO、发布模型、教师 NPZ 和归档只读；转换、缓存和审计写入本轮 `derived/` 目录。

### 3.3 将来运行上游生成器的条件

只有已发布数据不能满足某个明确训练需求时，才进入补生成：例如确需增加已分组的源演示，或改变目标箱体轨迹。补生成前登记数据需求、原演示分组、固定上游提交、G1/箱体版本、生成参数和失败分母。

现有 Holosoma checkout 固定提交为 `bccd4d7451640a2800ddc77e469d911a84f91994`。它与发布数据 revision 是不同对象，不能声称该代码必然逐字复现发布标签。

上游环境单独使用 uv 管理，优先验证 Python 3.12；核查其 NumPy 固定版本、CVXPY/Clarabel、mesh 依赖和实际 API。主项目的 `.venv`、Python 约束及 `uv.lock` 不用于承载上游不兼容依赖。先一段前向生成和回放，保存命令、环境及实际数值结果，再按需求扩展。

新生成输出仍属于近似动作教师，必须执行本方案的配对、数值和质量登记。上游成功退出不等于严格验收通过。

## 4. 独立训练数据协议

### 4.1 协议身份和用途

拟新增 `configs/labels/omniretarget_motion_v1.yaml`，协议标识为 `omniretarget_motion_v1`。这是**待实现的独立协议**，用途如下：

| 用途 | 本轮准入 | 限制 |
| --- | --- | --- |
| 根/关节动作重建 | 基础数值、资产和配对核查通过 | 标签为近似教师，允许已记录的运动学缺陷 |
| 教师 FK 拟合 | 同上，FK 适配核验通过 | 衡量对教师的拟合，不宣称人体任务质量 |
| 一般时序差分监督 | 连续有效帧对 | 不把教师速度当机器人允许速度 |
| 几何接近记录 | 距离证据可计算 | 只描述几何事实 |
| 手部接触辅助损失 | 首轮关闭；后续另登记可靠帧证据 | 人体参考接触标记不能代替机器人接触认证 |
| 严格可行标签或承重抓握标签 | 本协议不提供 | 仍须原独立验收和对应用途协议 |

文件有严格检查失败项，不自动取消其动作监督资格。文件存在身份、配对、单位或数值损坏，则不能作为动作标签。

### 4.2 必须通过的基础检查

逐文件检查并记录：

1. 三个必需字段存在；qpos 精确为 [T,43]，human_joints 精确为 [T,52,3]，T>0，fps 有限且与本轮 30 Hz 一致。不能只检查人体数组的前两个维度。
2. 根、关节、箱体和人体所有输入有限；四元数非退化。根/箱四元数单位范数误差 <=1e-4 可作明确记录的数值归一化，超过该范围拒绝该文件。归一化写入派生表示，不改原 NPZ。
3. 明确 NPZ 根和箱体为 `[qw,qx,qy,qz,x,y,z]`，内部为 `[x,y,z,qw,qx,qy,qz]`；PT 箱体为 `[x,y,z,qx,qy,qz,qw]`。转换和往返有解析用例。
4. 29 个关节与锁定资产逐名对应。本轮不裁剪关节教师标签；标签超出锁定关节范围时记录并拒绝该文件，不使用旧入口的自动 clamp。
5. 人体与教师帧数相等，源 PT 与对应 original 的帧对应关系通过；增强另核查其与父演示的帧对应。不得猜测重采样关系。
6. 身高缩放、旋转、平移、箱体原点和源/目标场景映射可重建。缺乏映射证据的文件不进入正式训练。
7. demo、variant、父关系、split 唯一且一致；跨分组、缺父文件、重复记录或未知命名显式报错。

位移/角度突跳作为数据审查项，首先检查时间断裂、坐标变化和单位错误。只对已证实的数据损坏作拒绝，不因超出 strict 速度界就将困难动作从训练或评估分母中删除。审查规则及处置在模型结果产生前冻结。

首轮不做平滑、速度投影、物体重采样或窗口内标签改写，以免把教师来源和新增处理效果混在一起。

### 4.3 源人体场景与目标机器人场景

这是本轮实施的明确前置问题。

[M0 审计](../verification/m0_verification.md)已发现：original 的目标箱体位置与变换后的 PT 箱体之间有每段常数偏移；rot/trans 中人体轨迹可能与 original 相同，而目标箱体和机器人场景改变。当前 `src/ireset/data/teacher.py` 却注释称增强一起移动人、机器人和箱体，并将 source_obj_pose 与 target_obj_pose 都取自当前 NPZ。该假设必须按实际数据重新核验。

实施要求：

- **源场景**保存参考人体实际对应的物体轨迹；**目标场景**保存给定的机器人任务物体轨迹。
- 复用 M0 相似变换方法，在派生记录中保存尺度、旋转、平移、目标偏移、源/目标几何尺度及时间映射。参考接触的表面距离需与源几何及单位一致。
- 映射参数只能由源参考、已知场景设置和发布元数据恢复；不利用目标机器人根、关节或 FK 构造推理条件。
- 有证据证明某种映射下两者相同，才可赋同值，并记录依据；不能因 schema 已有两个字段而认为语义已经正确。
- `kps_obj` 使用源物体系；目标箱体条件使用目标轨迹；参考接触从源人体场景推断。训练、生成、修复适配和评估必须消费同一版本的条件。
- 原始演示映射未核验时停止正式训练；增强映射未核验只阻止增强实验，不阻塞已核验 original-only 基线。

配对出口拟冻结为：相似变换后人体最大残差 <=1e-5 m、original 箱体姿态最大映射误差 <=1e-3 度、常数位置偏移的最大残差 <=1e-5 m。数值范围由已审计样本的舍入量级制定，属于配对正确性门。真实新增文件不满足时保留失败证据，核查转换或映射类型，不以放宽数值掩盖不同场景关系。

### 4.4 质量标记与严格检查

动作准入与质量标记分别保存。质量标记至少包括穿透、关节/根速度、脚滑、悬浮、手箱间隙、手部认证区间、累计锚漂和固定箱体输入的地面冲突。

train 的全量严格检查可以在初步训练后继续补齐，不能成为重新引入“所有教师严格通过才允许训练”的隐含门。未完成检查标为 `not_checked`，不填写 False、0 或通过。冻结验证集合的完整质量检查是初步结果报告的一部分。

质量标记不进入模型条件。首轮也不依据 strict 质量标记重加权动作损失，以便获得清楚的原始动作监督基线。

## 5. 清单、缓存和数据消费契约

### 5.1 清单

拟新增格式 `omniretarget_training_manifest_v1`。审计清单为全部候选保留行，训练入口仅消费 `admission.motion=true` 且属于请求分组的行。每行至少包含：

- demo、subject、variant、parent_demo、split、T、fps、窗口数量与唯一帧时长。
- 实际源 NPZ/PT 路径及完整 SHA-256；派生表示路径/哈希；发布数据 revision。
- 源/目标场景关系、变换记录、配对误差、几何和资产身份。
- 数值检查、动作准入及每项失败原因；完整质量标记和证据位置。
- 协议版本、配置摘要、代码 revision、时间及执行信息。

清单顶层保存原始候选数、已处理数、可用演示/文件/帧/窗口数、排除和待审查数，按 split/subject/variant 汇总。数量不足不能通过删清单行消失。

### 5.2 数据入口

在 `TeacherWindowDataset` 增加显式 `training_manifest` 入口，与旧 `label_manifest` 互斥。按协议分派；旧 graded 入口与无清单历史入口保持原用途。新训练 CLI 必须使用新清单，不悄悄回退到旧入口。

加载时核验协议、split、文件和配置哈希、T/fps、场景表示及资产；缺文件或身份漂移是运行错误，不能静默跳过。对明确记录的“不适合训练”行，保留排除原因而不创建窗口。

窗口沿用 F=60、stride=30，只在原始演示分组后切取。首轮只使用完整窗口，不增加 padding/mask 体系；因此不得声称现有损失已经支持任意有效帧 mask。

### 5.3 统计量和缓存

- 根位置统计只用准入后的 train 帧，每个文件的原始帧计一次，不按重复窗口累计；val/test 不参与。
- root_stats、条件缓存保存 train 清单摘要、源/目标映射版本和资产哈希；不同数据版本各自拟合，不能复用旧 258,462 帧统计冒充 original-only 统计。
- 接触缓存键至少包括源文件、条件映射、源几何、协议和推断配置的完整摘要。原 `m3_cache/schedules` 仅按名字缓存，不直接承接本轮新语义。
- 缓存原始 clip 级结果，不预保存重复滑窗。hash 失配重新生成新缓存或拒绝，不使用旧值。
- 接触 mask、教师质量标记和教师机器人状态属于监督/诊断侧；模型输入只保留可部署时已知的参考和任务条件。

## 6. 训练实验设计

### 6.1 首轮有限矩阵

| 实验 | 教师 | 模型 | 接触损失 | 目的 |
| --- | --- | --- | --- | --- |
| S0 | train 小样本，original-only | 两模型 | 0 | 数值烟测与小样本拟合 |
| T1-D | 全部准入 train originals | 确定性 | 0 | 快速预测与训练对照 |
| T1-F | 与 T1-D 同一清单 | 扩散，x0-prediction | 0 | 条件扩散主路线 |

两模型使用相同数据、条件、主干规模、动作损失、有效 batch 和优化步上限。先运行 T1-D，再 T1-F，单 GPU 不并行训练。首次正式训练均从头初始化，不混入旧教师/旧协议模型权重。

S0 只取 train 数据。验证过拟合用的同一小样本是调试证据，不计入泛化结果，也不据此选择教师。

### 6.2 固定起步配置

| 参数 | 本轮起点 |
| --- | --- |
| 主干 | d_model=240、4 层、6 头、FFN 倍数 4 |
| 动作窗口/步长 | 60/30 帧 |
| 时间注意力窗口 | 31 帧 |
| 状态 | 根平移 3 + 旋转 6D + 29 关节，输出解码为根位姿和关节角 |
| 扩散训练步数 | 1000，prediction_type=sample，clip_sample=False |
| 采样 | DDIM 25 步、eta=0、无 guidance |
| 优化器 | AdamW，lr=1e-4，weight_decay=1e-5 |
| batch | micro-batch=4，grad_accum=4，有效 batch=16 |
| 精度 | FP32；首轮不同时引入 AMP 或注意力后端切换 |
| 梯度裁剪 | 1.0 |
| 训练随机种子 | 20261008 |
| DataLoader | workers=4，每 worker 单线程；启动前验证进程和线程设置 |
| 起步训练预算 | 每模型 4,000 个 optimizer steps |
| loss 验证/完整生成验证 | 每 250 步/每 1,000 步 |

正式运行记录有效 scheduler 参数，包括 beta_schedule/start/end 等；配置中有字段不等于实际调度器已经使用。只对干净关节输出执行限位映射，不裁剪根或旋转，不裁剪前向高斯噪声。

### 6.3 损失

首轮复用当前可验证项：w_pos=1、w_rot6d=1、w_joint=1、w_geodesic=0.5、w_fk=2、w_vel=0.5、**w_contact=0**。

重建在已有标准化状态空间计算；旋转测地项单位 rad²；FK 项单位 m²；现有 vel 项是标准化状态的相邻帧差分拟合，不将其误称为物理速度约束。

接触项关闭时不执行手部 SDF/FK 分支，也不读取参考接触作为接触监督。现有 LossAssembler 在没有认证 mask 时回退到 batch.contact，且 w_contact=0 仍可能计算该分支；实施时需显式门控。不在本轮同时加入碰撞能量、Laplacian 或未标定接触项。

### 6.4 验证、选模与续行

- 不使用现有 CLI 的 val 前 60 文件或 Trainer 前 40 batches 截断作为正式验证。对全部准入 val originals 的训练窗口验证，并按有效样本/帧数正确加权。
- 扩散去噪验证使用固定 t/noise 集，保存身份；验证 RNG 与训练 RNG 隔离，避免验证重置训练随机序列。
- 每 1,000 步在全部条件有效的 31 个 val originals 上生成完整轨迹，扩散采用固定采样 seed=7；以演示宏平均 teacher-fit FK MPJPE 选 best。无效输出计失败；存在无效输出的 checkpoint 不通过遗漏演示获得最优分数。
- 若没有覆盖完整集合的有效 checkpoint，记录“未取得合格 best”；last 可用于失败诊断，仍保留全部失败行，不能改称 best 或跳过数值错误。
- 另保存 root RMSE、关节 MAE、根旋转误差、人体任务误差和生成失败数；teacher-fit 改善不能替代闭环质量。
- 每模型首先完成 4k。若最后三次完整生成验证从最早一次到最后一次的宏平均 teacher-fit FK 误差降低 >=1%，且没有新增无效输出，则按原配置追加一个 4k 块；8k 时同规则最多追加到 12k。否则停止当前训练并交付结果。
- 12k 为本轮单模型上限；不在同一轮无界搜索学习率、网络或教师筛选参数。改实现、超参或数据另登记实验，不覆盖原尝试。
- 当无法计算上述宏平均（坏输出、缺教师或证据不足）时不自动延长，先排查原因；可以交付初步失败结果。

保存 best/last，以及有限的块边界 checkpoint。续训必须保存并核验 optimizer、步数、RNG、数据清单、统计量和数据顺序状态；现有只保存模型的 checkpoint 不视作精确 resume。若恢复条件不足，以 warm_start 的新实验登记，不拼接为同一次完整运行。

### 6.5 初步结果之后的有限选项

以下均不属于首轮默认执行：

1. **T2：同来源增强。** 在增强源/目标语义核验后，加入 train 的公开 rot/trans 变体，val 仍评估同一 original 集。重新拟合 train 统计，登记变体采样权重，防止有更多变体的演示无意获得更大权重。与 T1 比较，仍优先 OmniRetarget 数据。
2. **T3：可靠接触辅助。** 仅在能提供有版本的局部认证证据时，做 w_contact=0 与一个预先登记权重的比较。认证必须逐侧、逐区间验证，并结合穿透/限位/速度等局部有效性；原轨迹其他区间失败不能被局部接近掩盖。AABB 零距离不等于三 site 对真实 hull 接触，需先核查代理偏差和接触目标语义。mask 为空时贡献零损失/零接触梯度；缺证据时停在 T1。
3. **T4：针对性教师处理。** 按第 9 节触发条件，对少量 train 失败族比较上游配置调整、局部修复或替代教师。不能直接扩为全量自研重生成。

初步结果足以支持下一项实验时，记录选择理由和单变量比较，不要求先达到最终 90% 接受率才进行诊断。

## 7. 评估协议与闭环对照

### 7.1 固定评估集合

在正式训练前冻结两级 val 集合：

- `val_originals_v1`：原 val 的全部 31 个原始演示，完整长度，用于生成拟合与最终裸输出检查。
- `val6_pilot_v1`：从原 val 按受试者各取一个演示，共 6 个，完整长度，用于首轮修复闭环。每个受试者按 `SHA256("20261008|" + demo)` 排序取首个，不读取质量或模型结果进行选择。

保存具体名单与哈希，不只保存抽样规则。不能将已反复调试的 diagnosis6 或 calibration24_train_v1 当作新的留出评估集。

所有预期演示保留结果行。条件错误、短轨迹不支持、生成失败、修复超时、最终拒绝分别记录；不得替换成更易样本。teacher-fit 在教师数值无效时为缺失，人体任务指标在参考有效时仍可计算；不足完整证据时不作完整宏平均选模或优劣裁决。

首轮闭环使用 sample seed=7。选定 checkpoint 的扩散裸输出另报告 seeds=7/17/27 的逐演示结果和变化范围；全部样本都计入，不按教师误差或修复成功选择最佳 seed。训练只有一个 seed，不将采样 seed 变化当成训练重复实验。

### 7.2 对照矩阵

| 方法 | 输入/处理 | 能说明什么 |
| --- | --- | --- |
| Teacher raw | 原始 OmniRetarget 标签直接回放 | 教师拟合参照与实际质量 |
| Teacher + repair | 原教师作为标准修复器初值 | 已有近似标签在当前修复器下的可修复性 |
| Deterministic raw | 条件输入，一次预测，拼接 | 确定性生成质量与成本 |
| Deterministic + repair | 同上，加标准修复与终检 | 确定性闭环 |
| Diffusion raw | 条件输入，DDIM-25，拼接 | 扩散生成质量与成本 |
| Diffusion + repair | 同上，加同一标准修复与终检 | 扩散闭环 |

Teacher + repair 读取了离线教师机器人初值，是诊断参照，**不能作为仅输入人类条件的可部署纯优化计时基线**。在没有固定版本上游从条件重新生成的完整成本之前，不宣称相对 OmniRetarget 的端到端加速。教师生成成本和学习训练成本分别登记。

教师关节噪声对照只在需要定位“模型误差还是修复器”时选做：固定 sigma=0.02 rad、seed=7、只扰动机器人关节，不扰动物体；记录限位处置和实际噪声大小。它不替代真实预测误差评估。

### 7.3 修复与验收冻结

首轮使用 `load_mode_configs("strict")` 的当前标准路径，显式锁定 `regen_mode=False`、无 R1/R2/R3 profile。保存实际 RepairConfig、ValidationConfig 和几何资产，而不是只保存 YAML 文件名。

当前标准路径的 task_mpjpe_tol_m 为 0.40 m。本轮将它明确标为**诊断工作值**，冻结后不因结果低而临时放宽。报告同时单列任务误差分布；历史 0.113 m 标定值带有选择偏差，可列为参照，不将其当作本轮已经重新标定的最终门。

保存 `robot_strict_pass`、`task_gate_pass`、`accepted_standard` 三项事实：求解器接受、独立机器人 strict 检查及本轮工作任务门均通过，才记 accepted_standard。该状态仍不等于完整主方案达标。

现有回放/修复常将固定输入箱体的 `box_ground` 对从机器人可行性裁决中排除。本轮必须保存 exclusions，额外报告固定箱体输入与地面的冲突：

- 输入箱体冲突属于场景输入问题，机器人修复不能通过移动已知箱体解决。
- 排除了 box_ground 的结果，只声明在已登记检查范围内的机器人轨迹通过，不声称完整场景无穿透。
- 其他碰撞族及插值检查不得为提高通过率而移除；保持既有允许对和检查范围。

生成候选和最终输出中的非有限/退化旋转都显式拒绝。有限次重采样仅用于数值退化，不按接触或任务分数挑样；保存实际尝试次数及最终有效性。

### 7.4 指标

**拟合与任务指标：**

- teacher-fit：根位置 RMSE（m）、根旋转测地误差（deg/rad）、关节 MAE（rad）、机器人 FK 对教师 FK 的 MPJPE（m）。
- task：机器人对应关键点对参考人体关键点的 MPJPE，保存世界/目标物体系视图，报告均值、p95 和逐演示值；不使用 teacher-fit 冒充 task。
- 连续性：根/关节速度分布、拼接边界差分与段内分布、窗口累计漂移、完整长度和失败位置。

**质量与接触指标：**

- 裸输出与修复后的穿透、限位、速度、脚支撑、手抓取检查；保留 failed_checks 及位置。
- 左/右手分别报告参考抓取帧、几何接近帧、认证总帧、认证与参考交集帧、最长连续交集以及累计锚漂。
- 双手同时认证交集帧数及最长连续区间单列；单手认证和近箱不能替代双手搬运证据。
- 接触 F1 报 defined 数量和未定义情况；没有认证区间不能获得“持续抓握通过”的结论。

**修复与成本指标：**

- 每个方法 expected、processed、accepted、rejected、timeout、error；处理数与集合身份必须完整对账。
- 整段接受率及失败类型，根/关节修改量，skip、SCP/QP 成本和重试；solver 未收敛不自动解释成物理无解。
- 在线总耗时包含条件构建、生成全部去噪调用、拼接、检查、修复、终检和所有重试；GPU 计时按边界同步，记录预热和冷/热缓存。
- 报告全预期集合总耗时、成功轨迹/小时，以及共同接受样本上的配对质量和耗时。共同集合为空时为 undefined，不能通过只统计成功样本制造加速。

以原始演示为宏平均单位。窗口、帧和扩散多次采样不作为独立演示数；可同时报告帧加权值，但必须标明。

### 7.5 最终测试边界

本轮主要交付 val 的初步结果，不默认执行 test 闭环。模型、教师协议、修复配置及评估代码冻结后，另登记最终测试执行。

旧 24 段历史标定含 19 train/2 val/3 test，此外历史审计或回放可能暴露更多 test。整理每个原演示的历史使用与暴露清单；未能追溯的状态记 unknown，不宣称该 test 完全未见。已有分组保持，不为了恢复“干净测试”叙述而重洗演示。

## 8. 分阶段执行与出口

| 阶段 | 必须完成的工作 | 出口与失败处置 |
| --- | --- | --- |
| A：冻结与配对 | 来源/资产/原分组核验、全 original 基础审计、场景映射、val 名单、协议和输入哈希 | 每个候选有判定；身份/条件不可靠先修；strict 缺陷只登记 |
| B：数据与接口 | 新协议/清单入口、独立缓存及 train 统计、显式配置 CLI、评估完整长度支持 | 数据可追溯，加载与推理条件一致，无监督条件泄漏 |
| C：数值烟测 | train 小集合，双方至少 100 optimizer steps；小样本重复拟合至多 1,000 步 | 输入/梯度/损失/输出有限；小样本重建趋势合理，失败先定位代码/条件 |
| D：初步训练 | T1-D/T1-F 各 4k，完整 val 选模，按 §6.4 有限续行 | 两模型 checkpoint、曲线和完整生成验证；失败可以作为证据交付 |
| E：初步结果 | val31 裸输出质量、val6 全长度六方法对照、成本及逐演示失败证据 | 固定集合全对账，报告初步成功或失败；不要求 accepted>0 才能结束 |
| F：路线判断 | 按 §9 定位主要瓶颈，确定维持训练、同来源增强、修复器处理或小规模教师比较 | 形成有证据的下一实验；不自动启动其他教师或全量生产 |

正式训练就绪门：A/B 正确性核验通过、全部 250 个 train originals 有准入/拒绝记录、六受试者各有可用训练窗口、训练数据量满足实际 batch、C 完成。若某受试者全部基础核查失败，则先解释原因；小子集只能标调试结果。

该门不包含旧 6/6、18/24、所有教师 strict 通过或最终接受率 90%。训练集数量和覆盖不足仍需如实说明，不能将“能够训练”解释为“数据已充分”。

E 的完成要求是完整、可核验的比较证据。全拒时交付 0/N 及失败分类，不因结果为零无界修复到成功，也不删困难演示。预算中止或缺方法时标 INCOMPLETE，不写完整比较通过。

## 9. 何时处理或更换教师

### 9.1 诊断与下一动作

| 观察到的现象 | 优先解释与动作 | 教师替换条件 |
| --- | --- | --- |
| 小样本也拟合不了 | 检查条件、编解码、梯度、数据顺序和优化实现 | 不由此触发换教师 |
| train 拟合好、val 明显变差 | 过拟合、覆盖、条件一致性；先比较 OmniRetarget 同来源增强 | 除非证实该来源缺少所需任务覆盖 |
| 生成对教师误差仍在明显下降 | 按有限预算继续训练，暂不改变教师 | 尚无必要性证据 |
| 教师自身与模型复现同类滑移/悬浮/漂移 | 可能为标签缺陷；比较局部修复或上游约束设置 | 需要拟合已足够且瓶颈归因成立 |
| Teacher + repair 与两模型同族拒绝 | 修复器、约束语义或输入可达性；以冻结失败用例取证 | 不能仅据共同失败替换教师 |
| Teacher + repair 通过、模型修复失败 | 预测误差和修复容域；检查生成与拼接 | 优先改善生成或修复鲁棒性 |
| 固定箱体输入与地面冲突或明显不可达 | 输入场景/任务范围，显式拒绝和登记 | 需改变任务设置，不能只换机器人标签 |

teacher-fit 误差小没有统一的任意数值门：结合根、关节、手部 FK、教师缺陷幅度和实际修复敏感性判断。要将教师列为主瓶颈，至少提供 **3 个不同 train 原始演示** 的同族证据，逐例比较 Teacher raw、模型 raw、Teacher + repair、模型 + repair，说明预测误差与教师缺陷的量级。三例用于避免单例误判，不构成总体统计证明。

### 9.2 小规模教师比较的要求

触发后另登记最多 12 个 train 原始演示，覆盖失败族和同类成功对照；固定目标物体、模型资产、原分组和输出验收口径。优先次序为上游参数/约束配置、现有教师局部修复、其他生成方法。先改变一个因素，避免全量替换后无法归因。

比较至少报告：原始分母、可用动作时长/窗口、可靠双手监督量、任务误差、全成本、失败分布和所需标签修改。要声称新教师更有训练价值，还应在可比数据覆盖和训练预算下比较模型闭环，而不能只比较离线接触指标。

新来源只接触 train；val 只用于预先登记的选择，test 不用于筛选。旧教师、新教师、局部修复和增强保留来源与父演示关系。发生更换时保留 T1 的模型、数据清单和结果作为主来源基线。

2. 原始人体不动而目标物体增强时，源/目标条件分离；带常数 z 偏移的 original 不被误认为完全同场景；相似变换解析用例成立。
3. 同演示变体不能跨 split；重复/缺父/哈希漂移/协议错拒绝；旧 graded 和历史入口仍按各自契约消费。
4. 修改 val/test 不改变 train root_stats；修改映射/配置/输入使缓存失效；统计不重复计算重叠窗口。
5. w_contact=0 不执行接触分支且无接触梯度；开启时缺证据拒绝或按已登记的全零 mask 处理，不回退人体参考标记。
6. 验证不污染训练 RNG，验证覆盖和加权正确，保存的 best 确来自完整生成指标；空/坏输出不改善选模分数。
7. 全长度包含最后窗口；一个生成失败/一个超时仍保留 expected 分母；最后输出非有限或退化不能 accepted。
8. 同一数据与 checkpoint 的确定性生成复跑一致，扩散固定 seed 可复现；计时含全部采样调用和失败尝试。

实施时先跑相关测试，代码冻结前执行 `uv run --locked pytest tests/ -q`，记录实际结果。359 passed+1 skipped 为最近工程验收快照，不预设本轮测试总数。本次文档修改只做 diff、引用和结构检查。

## 12. 资源预算与停止条件

### 12.1 起步预算

预算是运行上限与调度建议，不是时间保证：

| 工作 | 起步运行预算 | 达到上限后的处置 |
| --- | --- | --- |
| 基础审计、配对与新缓存 | 2 小时 | 分段保存已处理数；缺项不宣称就绪，按实测登记剩余工作 |
| S0 数值烟测与小样本拟合 | 合计 1 小时、每模型最多 1,000 步 | 不通过先定位实现，不启动全数据训练 |
| T1 训练 | 每模型首块 4k；本轮最多 12k/模型，累计 GPU 墙钟上限 12 小时 | 按 §6.4 续行；到总上限保存 last 和 incomplete，不追加超参搜索 |
| val31 裸输出与质量登记 | 2 小时 | 保留逐方法进度，未完成不能称完整裸输出比较 |
| val6 闭环 | 主 seed 合计最多 18 次 repair，初始墙钟上限 6 小时 | 不删长段、不改阈值；超时记录并交付 incomplete 和成本证据 |

上表只限制实验运行资源，接口开发和正确性修复的工时另记。GPU 训练墙钟包含该训练过程中的验证；数据审计、最终回放与 CPU repair 成本另列，不把阶段预算当算法耗时。

首个 200 步测量当前训练 ms/optimizer step、峰值显存、验证额外成本。首个完整 val repair 后更新剩余预算估计并记录，不从某个异常负载点直接外推全天。预算调整只改变资源上限，另登记理由，不新增实验候选或样本筛选。

初步 val6 后是否扩大到全部 val31 修复，依据实测全成本和诊断收益决定；它不是首轮交付的默认前置。扩大时保持同配置及名单，登记新的完整 expected 集和预算。

### 12.2 本机配置与存储

沿用 Python 3.12.x、项目 `.venv`、`uv run --locked`；新增依赖按实际缺口通过 uv 维护，首轮优先现有 NumPy/SciPy、MuJoCo、pytorch_kinematics、PyTorch/Diffusers 和 threadpoolctl。

单张 RTX 3090 24 GiB，训练 sequential。起步 micro-batch=4、累积=4；OOM 时先减少 micro-batch 并增加累积维持有效 batch=16，保存变更。修复和数值对拍为 float64。预处理先 workers=4、native_threads=1；实际采样检查是否有收益，再决定并发。

大量写入和训练前重新检查磁盘、GPU 与 CPU 占用。检查点保留 best/last 和有限块边界，避免逐步存档；缓存按 clip 保存。失败 trace 只对代表性冻结用例保存完整数值，其余保留足够定位的摘要，防止再次形成无界产物。

### 12.3 停止与错误分类

- 身份/配对/条件泄漏、数值坏值或源文件修改：停止相关阶段，修正确性并重验受影响结果。
- 无有效数据或不足构成 batch：数据就绪失败，报告实际覆盖，不用空 loader 或空验证获得零损失。
- worker 崩溃、GPU OOM、磁盘不足：工程失败或 incomplete，不记运动学不可行。
- 修复拒绝、无 merit step、信赖域塌缩：保存具体失败位置和事实，不自动改教师或求解参数。
- 完整结果均拒绝：可完成本轮诊断交付；仍是闭环失败，不宣称方法达标。
- 上限到达：保存实际消耗与剩余 expected，复用完整任务，禁止部分集合 PASS。

## 13. 初步结果的交付格式

报告至少包含以下相互对应的证据：

1. **数据表**：原始候选与准入数量、各 split/subject 时长、独立演示和窗口、排除原因、教师质量检查完成度。
2. **训练表与曲线**：两模型配置、步数、验证选模、数值失败、峰值显存、训练/验证成本，明确是否仍在改善。
3. **val31 裸输出表**：教师拟合、人体任务误差、拼接与完整几何检查，逐演示及宏平均，多采样变化范围。
4. **val6 闭环表**：六方法的 expected/processed、接受/拒绝、逐类失败、接触与双手认证、修复幅度和总成本。
5. **代表性回放**：至少 3 个不同 val 演示，按成功/失败类别确定性选取，展示人体、固定箱体、教师、预测、修复结果；全部失败时仍展示失败及位置，不制作只有成功的演示集。
6. **路线判断**：继续当前训练、同来源增强、条件/修复器问题、教师处理或证据不足；每项判断指向具体清单/结果，不以主观观感替代比较。

初步成功的含义是得到可靠且有解释力的基线，不自动代表可承重抓握、动力学可行、RL 可跟踪或真机部署。
