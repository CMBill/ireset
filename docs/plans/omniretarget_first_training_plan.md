# OmniRetarget 优先教师与初步训练执行方案

初版日期：2026-10-08。修订日期：2026-10-09。修订：v3，教师来源比较前置，初步训练不依赖自研修复。状态：**推进方向已由用户明确，本文件为执行方案；本次仅更新文档，尚未实施新接口、生成新教师或启动训练。**

本轮目标是先使用 OmniRetarget 工具与数据获得可解释的动作学习基线。考虑到已发布教师存在已知接触缺陷，先在固定 train 小样本上比较发布教师与本地 OmniRetarget 生成结果，明确主训练标签来源，再开展初步训练。初步训练不再以自研教师重生成的六段门或 train24 门通过为前置。

v2 修订原因：v1 默认将发布数据作为主训练来源，把本地生成放在后续补数据阶段。历史证据已经足以要求提前比较教师质量；关闭接触损失也不能阻止状态/FK 重建学习悬浮、滑移和漂移。该修订调整来源决策和执行顺序，不预设本地重跑会改善质量，也不要求先取得全部严格可行教师。

v3 修订原因：用户判断当前自研修复器不足以承担上述功能。本轮据此按“修复能力不足”安排工作，移除默认在线修复及必做修复对照，不假定它能补救教师悬浮、脚滑、手锚漂移或模型预测误差。该判断是本轮执行前提，历史 R 候选失败仍保留其原有配置和样本范围，不扩写为所有标准修复场景均失败的新实测结论。

**默认流程为 OmniRetarget 教师比较与生成 → 动作训练 → 裸输出独立检查。** 独立验收器用于测量、裁决和拒绝，不负责修改轨迹；自研修复器保留为已有代码和历史研究结果，仅在另立有限实验后作诊断。教师来源相对改善、模型拟合成功和可行交互输出是三种不同结论；前两者不能代替第三者。

## 1. 决策与历史方案的关系

### 1.1 已确定的推进方向

1. 优先采用 OmniRetarget 路线。发布数据先作为质量对照、场景配对依据和可选热启动，不自动视为高质量主训练标签。
2. 配对和资产核查后，在固定 train 小集合上用上游工具生成，按 §3.3–§3.5 比较并登记教师选择。本地生成有实际改善才优先扩大；无改善时保留“发布数据仅作弱监督诊断”或“来源未就绪”的明确裁决。
3. 来源决定后，以同一来源、同一固定配置的近似动作标签训练确定性预测器与条件扩散模型。先小批生成和初步训练，不等待全部 250 个 train 演示生成完成。
4. 自研修复器退出本轮默认执行流程；独立验收器直接检查教师与模型裸输出，报告质量并拒绝不合格轨迹。本轮不增加修复能力前置试验或等待修复器改进。
5. 第一轮以动作生成能力为主，手部接触损失默认关闭；可靠接触监督作为后续有限增量实验。
6. 初步结果后决定是否扩大同来源数据或处理教师。本轮不启动全量自研重生成、R 候选追加搜索或其他教师方法开发。

### 1.2 对既有阶段门的影响

本方案新增一条独立的“OmniRetarget 动作监督训练”路线，采用独立的数据协议和运行目录。

- [train24fix3 收敛恢复方案](train24fix3_convergence_recovery_plan.md)及其[验证记录](../verification/train24fix3_convergence_recovery_verification.md)中的 D+ 终局保留：R1/R2/R3 分别为 1/6、1/6、2/6，winner=None。
- 自研严格教师生产路线的 train24、312 originals 重生成及其干净标签重训继续暂停；本方案不将其改记为通过。
- 新动作训练路线由本文件的教师来源比较、数据、接口和数值正确性门驱动，允许使用存在已记录运动学缺陷的近似教师，不等待上述生产门。
- [graded_labels_v1](../../configs/labels/graded_labels_v1.yaml)继续适用于其原有严格教师用途；本方案不修改其准入含义，也不将失败轨迹伪装成该协议的合格标签。
- [主方案](interaction_retarget_impl_plan.md)的最终整段质量目标、接受率和加速要求继续有效。本轮是初步基线，不以训练完成代替最终达标。

新增训练协议不改变输出碰撞、限位、速度、脚支撑和手抓取验收阈值。

主方案中“条件扩散 + 顺序 QP 修复”的路线保留为最终研究目标，其修复能力前提尚未满足。本轮交付动作学习基线；若裸输出不能满足任务与独立验收要求，最终可行输出、接受率和加速目标仍未实现。后续修复器改进、替代优化器或任务范围调整须另立方案，不自动占用本轮训练预算。

### 2.2 核心问题

本轮按顺序回答：

1. 条件和资产是否对齐；本地 OmniRetarget 生成是否在相同任务上改善了发布教师的已知缺陷？
2. 选定来源能提供多少可追溯的动作监督，模型是否能拟合小规模训练样本？
3. 在固定验证演示上，模型能否复现教师的全身动作和人与箱体的任务关系？
4. 教师、确定性预测和扩散预测的裸输出各有哪些穿透、脚滑、悬浮、漂移和连续性缺陷？生成与独立检查的完整成本是多少？
5. 当前证据能否区分条件构造、模型拟合、教师缺陷与固定输入问题；若仍缺少有效可行性处理，哪些最终目标尚未实现？

“教师有缺陷”不能单独推出“应替换教师”；“模型已拟合教师”也不能单独推出“输出可行”。

## 3. 教师来源、资产和数据范围

### 3.1 首轮使用范围

首轮任务范围为原始演示对应的 source/target 场景，不引入 rot/trans 变体。发布 `*_original.npz` 是比较参照；本地生成结果保存独立来源身份，不因文件后缀相同而混用。

- 训练候选：原 train 的 250 个原始演示；教师比较只接触 train。
- 本地来源选定后的首批训练目标为 24 个固定 train 演示，每受试者 4 个；初步结果后再扩大至 250。该集合与历史 calibration24_train_v1 是不同用途的清单，不套用旧 18/24 keep 门。
- 验证候选：原 val 的 31 个原始演示。使用本地教师时，以选定冻结配置生成对应 val 标签；不利用其质量调整上游配置。
- 测试：保持原 test 的 31 个演示，本轮不用于模型或规则选择。
- 17 个没有公开教师的 PT 保持 reserve 身份，本轮不补生成、不直接加入 train。
- T<60 的轨迹不用于首轮训练窗口；短轨迹的独立演示和时长单列。评估中不得因为长度或失败静默缩小已冻结分母。

数据审计可以登记 test 的身份、格式与配对，不能据 test 的任务、接触或可行性指标调整训练和筛选策略。

### 3.2 来源和资产锁定

发布数据 revision 固定为 `135259130158f1cb1799e4ab9b6566c938285fc9`。记录下载归档、实际读取的 NPZ、配套发布模型、项目锁定 G1/箱体资产的完整 SHA-256。

项目目标资产继续使用普通手的 G1 29-DoF 锁定版本，不混入 spherehand。发布资产与项目资产分别登记，核查关节名称/顺序、关节轴、根坐标、mesh 缩放、箱体原点和手部碰撞代理。运动学一致性不足时先修正适配；格式、碰撞代理差异本身不自动触发完整教师重写。

源 OMOMO、发布模型、教师 NPZ 和归档只读；转换、缓存和审计写入本轮 `derived/` 目录。

### 3.3 前置本地生成试验

在 train 每个受试者内按 `SHA256("20261008|teacher_pilot|" + demo)` 排序取首个，冻结 `teacher_pilot_train6_v1`，共 6 个原始演示，全部完整长度。先保存具体名单、输入/场景/资产和配置哈希，再读取本轮质量结果。既有 diagnosis6 可作为历史解释材料，不替换新名单。

比较矩阵严格有限：

| 来源 | 内容 | 执行规则 |
| --- | --- | --- |
| P | 已发布 original 教师 | 用当前锁定验收几何重新回放，作为固定质量参照 |
| U0 | 固定上游代码在本地生成 | 资产、条件和时间适配明确；保存实际优化配置，首次不进行结果驱动调参 |
| U1 | 可选的一项有依据的上游配置调整 | 仅当 API 核查发现与已知缺陷直接相关且已支持的能力时，在读取新生成质量前冻结唯一差异；否则记 not_applicable |

U0 与 P 的代码、生成环境或资产差异可能不止一项，逐项登记，不声称纯粹复现或唯一因果。U1 与 U0 的差异必须闭合，不能临场追加第三个候选。

同版本、同配置重跑不保证提高质量。允许的工作优先为核实坐标/几何、使用已有 API 和有证据的配置修正；不能假定上游存在持续手锚或手面硬接触开关。若所需能力缺失，记录缺口，本轮不借此开发另一套重定向求解器。

现有 Holosoma checkout 固定提交为 `bccd4d7451640a2800ddc77e469d911a84f91994`。它与发布数据 revision 是不同对象，不能声称该代码必然逐字复现发布标签。

上游环境单独使用 uv 管理，优先验证 Python 3.12；核查其 NumPy 固定版本、CVXPY/Clarabel、mesh 依赖和实际 API。主项目的 `.venv`、Python 约束及 `uv.lock` 不用于承载上游不兼容依赖。先一段前向生成和回放核查真实 API，再执行冻结六段；环境或适配失败是工程问题，不作“OmniRetarget 标签质量无改善”的裁决。

三来源必须绑定同一个源人体参考、固定目标箱体轨迹、fps/T、地面和任务范围。若上游默认流程重缩放或改写目标箱体，先通过薄适配恢复明确的输入契约；绑定不成立的结果不能参与配对质量比较。不得借移动箱体、截短动作、改变速度或替换手模型获得改善。

首轮 U0/U1 采用仅依赖参考与任务的上游初始化。若需试验发布机器人轨迹热启动，另登记为 oracle-warm-start 的独立诊断，不能混进 U0/U1 或宣称可部署生成。

新生成输出仍属于近似动作教师，必须执行本方案的配对、数值和质量登记。上游成功退出不等于严格验收通过。

### 3.4 质量比较与来源裁决

P/U0/U1 使用同一当前验收器和插值协议。固定输入箱体问题按 §7.3 单列，三来源一致处理。全部 6 个预期演示保留行，报告生成失败、处理数量和成本，不只比较成功子集。

质量至少比较：机器人碰撞穿透最大值及违规帧比例；固定参考支撑区间内脚面高度、脚速度和漂移；固定参考抓取区间的左右手间隙 p95、接近覆盖、认证交集和双手重叠；携带期手部相对运动/累计漂移；人体任务 MPJPE；数值有效性和可用时长。

接近覆盖单独附加“没有超容差机器人穿透”的有效覆盖统计，避免深穿透被 `distance < enter` 当成改善。脚/手评估使用相同参考区间；认证区间减少、悬空或无区间不能自动改善速度/漂移指标。所有空分母/证据缺失为 undefined。

双手比较的公共分母为源参考左右抓取同时成立的帧；双手有效接近要求两侧最近手部几何间隙均 <0.01 m，且该帧最大机器人穿透 <=0.002 m。双手间隙序列为 `max(0,left_gap,right_gap)`，对同一公共分母取 p95。无双手参考帧不产生改善分数；最终认证与这些接近统计分别报告。

本轮优先验证已知手部悬浮是否改善，拟冻结的本地优先判据为：

1. 预期集合和来源身份完整，条件绑定通过；数值有效的可用演示/帧数量不低于 P，不能靠拒绝难例提高质量。
2. 每个演示的 task MPJPE p95 不高于 P+0.02 m。
3. 每个演示的最大机器人穿透不高于 `max(P,0.002 m)`；对存在固定参考支撑帧的演示，脚速度 p95 和离地间隙 p95 不高于 `max(P,对应 strict 界)`，比较舍入容差分别为 1e-6 m/s、1e-6 m。无参考支撑帧时不计算该脚指标，不作为改善分数；有参考帧但缺测量为证据不足。违规比例与漂移同时报告，存在新增严重失败或明显退化时不记优先。
4. 至少 3 个不同演示的双手有效接近覆盖增加 >=10 个百分点，或双手参考抓取区间的间隙 p95 降低 >=25%；两者中使用的主指标先登记、全演示报告。P 间隙 p95 为零时不能获得相对降低分数；没有双手参考抓取的演示不因空分母获得改善。
5. 接触改善未以更大穿透、漂移、脚滑、任务误差或修改固定输入换取；不将一个指标的改善概括为可靠抓握。

这些是工程路线选择标准，允许参考水平以下的残余缺陷，不要求六段全部 strict 通过，也不构成统计显著性、全库质量或承重证明。U0 优先；仅 U0 不满足且已预注册 U1 时执行 U1。U0 满足则 U1 记 not_needed。

由于本轮没有可靠修复兜底，选择必须基于未经过自研修复的教师结果，单列实际残余缺陷。`local_preferred` 只授权近似动作标签的小批训练，不说明标签能够被修成可靠搬运，也不授权可行交互输出或全量生产。残余质量不足时，可停止当前来源推进并登记缺口；不能用“训练后再修”解释继续投入的合理性。

输出 `teacher_selection.json`，包含具体来源/配置、各项判据、原始分母、成本、残余风险与以下裁决之一：

- `local_preferred`：本地来源有明确改善，进入小批生产及初步训练。
- `no_quality_gain`：完整比较没有证明本地改善；不启动全量重跑。可登记发布数据的受限动作预训练/诊断基线，目标为 `weak_motion_only`、接触损失为零、每模型最多 4k；不得称高质量搬运教师训练。
- `incomplete` 或 `not_ready`：缺来源/身份/处理证据，或条件/环境尚未成立；修复具体问题，不自动回退发布数据冒充已完成来源选择。

比较结论与实际训练来源分开记录。选择弱监督诊断须写明为何仍有信息价值；不能忽略已知标签缺陷默认进入 12k 主训练。

### 3.5 来源选择后的生产与新增数据

`local_preferred` 后按同一 hash 排序取每受试者前 4 个 train 演示，包含 pilot 六段，冻结 `teacher_production_train24_v1`。先生成这一批以及 val31 对应标签，登记全部成功/失败；数值和配对合格的标签可用于初步动作训练，不要求 24/24 strict 或旧 18/24 keep。

上游版本、资产、初始化与配置在生产中冻结；val 标签的失败不用于修改配置，不静默改用 P 标签填洞。教师生成失败不应导致有效参考条件从生成评估分母消失，缺 teacher-fit 的项目按 §7.1 处理。

初步结果后才扩大到其余 train originals。17 个 reserve、新任务或不同目标箱体轨迹的补生成另登记分组、需求和场景身份。可在来源比较完成后安排受限弱监督诊断，但发布数据和本地生成数据不能无标记混成同一清单。

| 用途 | 本轮准入 | 限制 |
| --- | --- | --- |
| 根/关节动作重建 | 教师来源裁决已登记，基础数值、资产和配对核查通过 | 标签为近似教师，允许已记录的运动学缺陷；弱监督分支单独命名 |
| 教师 FK 拟合 | 同上，FK 适配核验通过 | 衡量对教师的拟合，不宣称人体任务质量 |
| 一般时序差分监督 | 连续有效帧对 | 不把教师速度当机器人允许速度 |
| 几何接近记录 | 距离证据可计算 | 只描述几何事实 |
| 手部接触辅助损失 | 首轮关闭；后续另登记可靠帧证据 | 人体参考接触标记不能代替机器人接触认证 |
| 严格可行标签或承重抓握标签 | 本协议不提供 | 仍须原独立验收和对应用途协议 |

文件有严格检查失败项，不自动取消其动作监督资格。文件存在身份、配对、单位或数值损坏，则不能作为动作标签。`admission.motion=true` 只说明可以消费近似动作，不能替代 `teacher_selection` 的来源判断；降低标签用途也不能证明原质量问题已解决。

### 4.2 必须通过的基础检查

逐文件检查并记录：

1. 三个必需字段存在；qpos 精确为 [T,43]，human_joints 精确为 [T,52,3]，T>0，fps 有限且与本轮 30 Hz 一致。不能只检查人体数组的前两个维度。
2. 根、关节、箱体和人体所有输入有限；四元数非退化。根/箱四元数单位范数误差 <=1e-4 可作明确记录的数值归一化，超过该范围拒绝该文件。归一化写入派生表示，不改原 NPZ。
3. 明确 NPZ 根和箱体为 `[qw,qx,qy,qz,x,y,z]`，内部为 `[x,y,z,qw,qx,qy,qz]`；PT 箱体为 `[x,y,z,qx,qy,qz,qw]`。转换和往返有解析用例。
4. 29 个关节与锁定资产逐名对应。本轮不裁剪关节教师标签；标签超出锁定关节范围时记录并拒绝该文件，不使用旧入口的自动 clamp。
5. 人体与教师帧数相等，源 PT 与对应 original 的帧对应关系通过；增强另核查其与父演示的帧对应。不得猜测重采样关系。
6. 身高缩放、旋转、平移、箱体原点和源/目标场景映射可重建。缺乏映射证据的文件不进入正式训练。
7. demo、variant、父关系、split 唯一且一致；跨分组、缺父文件、重复记录或未知命名显式报错。

位移/角度突跳作为数据审查项，首先检查时间断裂、坐标变化和单位错误。只对已证实的数据损坏作拒绝，不因超出 strict 速度界就将困难动作从训练或评估分母中删除。审查规则及处置在模型结果产生前冻结。

对发布标签和本地生成输出，本轮不作额外平滑、速度投影、物体重采样或窗口内标签改写。上游生成自身改变机器人标签属于明确记录的教师方法；它不能改变已绑定的物体轨迹或时间轴。

### 4.3 源人体场景与目标机器人场景

这是本轮实施的明确前置问题。

[M0 审计](../verification/m0_verification.md)已发现：original 的目标箱体位置与变换后的 PT 箱体之间有每段常数偏移；rot/trans 中人体轨迹可能与 original 相同，而目标箱体和机器人场景改变。当前 `src/ireset/data/teacher.py` 却注释称增强一起移动人、机器人和箱体，并将 source_obj_pose 与 target_obj_pose 都取自当前 NPZ。该假设必须按实际数据重新核验。

实施要求：

- **源场景**保存参考人体实际对应的物体轨迹；**目标场景**保存给定的机器人任务物体轨迹。
- 复用 M0 相似变换方法，在派生记录中保存尺度、旋转、平移、目标偏移、源/目标几何尺度及时间映射。参考接触的表面距离需与源几何及单位一致。
- 映射参数只能由源参考、已知场景设置和发布元数据恢复；不利用目标机器人根、关节或 FK 构造推理条件。
- 有证据证明某种映射下两者相同，才可赋同值，并记录依据；不能因 schema 已有两个字段而认为语义已经正确。
- `kps_obj` 使用源物体系；目标箱体条件使用目标轨迹；参考接触从源人体场景推断。训练、生成和独立评估必须消费同一版本的条件；后续若另立修复实验，其适配也遵循这一契约。
- pilot 六段及实际训练/验证集合的原始演示映射未核验时，停止对应比较或正式训练；不必为六段试验先处理其余未使用演示。增强映射未核验只阻止增强实验，不阻塞已核验 original-only 基线。

配对出口拟冻结为：相似变换后人体最大残差 <=1e-5 m、original 箱体姿态最大映射误差 <=1e-3 度、常数位置偏移的最大残差 <=1e-5 m。数值范围由已审计样本的舍入量级制定，属于配对正确性门。真实新增文件不满足时保留失败证据，核查转换或映射类型，不以放宽数值掩盖不同场景关系。

### 4.4 质量标记与严格检查

动作准入与质量标记分别保存。质量标记至少包括穿透、关节/根速度、脚滑、悬浮、手箱间隙、手部认证区间、累计锚漂和固定箱体输入的地面冲突。

pilot 的 P/U0/U1 及首批实际用于训练的教师必须完成质量登记；不要求全部检查通过，也不能把尚未检查当作通过。未使用的其余 train 全量严格检查可以后续补齐，不能成为重新引入“所有教师严格通过才允许训练”的隐含门。未完成检查标为 `not_checked`，不填写 False、0 或通过。冻结验证集合的完整质量检查是初步结果报告的一部分。

质量标记不进入模型条件。首轮不依据 strict 标记对动作损失做逐帧重加权；教师来源、用途和残余缺陷明确登记，避免将来源选择与复杂重加权同时改变。

## 5. 清单、缓存和数据消费契约

### 5.1 清单

拟新增格式 `omniretarget_training_manifest_v1`。审计清单为全部候选保留行，训练入口仅消费 `admission.motion=true` 且属于请求分组的行。每行至少包含：

- demo、subject、variant、parent_demo、split、T、fps、窗口数量与唯一帧时长。
- 实际源 NPZ/PT 路径及完整 SHA-256；派生表示路径/哈希；source_type（published/upstream_generated）、发布数据或上游代码 revision。
- teacher_selection 路径/摘要、生成配置/环境/初始化身份、production_cohort、训练用途；可用的发布参照另存，不覆盖来源信息。
- 源/目标场景关系、变换记录、配对误差、几何和资产身份。
- 数值检查、动作准入及每项失败原因；完整质量标记和证据位置。
- 协议版本、配置摘要、代码 revision、时间及执行信息。

清单顶层保存原始候选数、已处理数、可用演示/文件/帧/窗口数、排除和待审查数，按 split/subject/variant 汇总。数量不足不能通过删清单行消失。

### 5.2 数据入口

在 `TeacherWindowDataset` 增加显式 `training_manifest` 入口，与旧 `label_manifest` 互斥。按协议分派；旧 graded 入口与无清单历史入口保持原用途。新训练 CLI 必须使用新清单，不悄悄回退到旧入口。

加载时核验协议、split、文件和配置哈希、T/fps、场景表示、资产及教师选择；缺文件或身份漂移是运行错误，不能静默跳过。对清单中明确记录的生成失败/不适合训练行，保留原因而不创建窗口。请求本地教师时不能回退发布轨迹填洞。

窗口沿用 F=60、stride=30，只在原始演示分组后切取。首轮只使用完整窗口，不增加 padding/mask 体系；因此不得声称现有损失已经支持任意有效帧 mask。

### 5.3 统计量和缓存

- 根位置统计只用选定来源和当前 production_cohort 准入后的 train 帧，每个文件的原始帧计一次，不按重复窗口累计；val/test 不参与。
- root_stats、条件缓存保存 train 清单摘要、源/目标映射版本和资产哈希；不同数据版本各自拟合，不能复用旧 258,462 帧统计冒充 original-only 统计。
- 接触缓存键至少包括源文件、条件映射、源几何、协议和推断配置的完整摘要。原 `m3_cache/schedules` 仅按名字缓存，不直接承接本轮新语义。
- 缓存原始 clip 级结果，不预保存重复滑窗。hash 失配重新生成新缓存或拒绝，不使用旧值。
- 接触 mask、教师质量标记和教师机器人状态属于监督/诊断侧；模型输入只保留可部署时已知的参考和任务条件。

## 6. 训练实验设计

### 6.1 首轮有限矩阵

| 实验 | 教师 | 模型 | 接触损失 | 目的 |
| --- | --- | --- | --- | --- |
| S0 | 选定来源的 train 小样本，original 场景 | 两模型 | 0 | 数值烟测与小样本拟合 |
| T1-D | local_preferred 的首批 train24 准入标签 | 确定性 | 0 | 本地近似教师的快速预测与训练对照 |
| T1-F | 与 T1-D 同一清单 | 扩散，x0-prediction | 0 | 本地近似教师的条件扩散主路线 |
| W1-D/W1-F | no_quality_gain 后登记使用发布 original 标签 | 两模型 | 0 | 可选的弱监督诊断；每模型最多 4k，不自动接入 T1 续行 |

T1 与 W1 是来源裁决后的互斥路线，本轮不默认训练四个模型。W1 同样使用按 §3.5 规则冻结的 train24 演示，消费其中基础准入的发布 original 标签，明确为有限弱动作监督；不将同名称原始演示与本地教师无标记混合，不自动扩大到全部发布数据。

每条路线的两模型使用相同数据、条件、主干规模、动作损失、有效 batch 和优化步上限。先确定性、再扩散，单 GPU 不并行训练。首次正式训练均从头初始化，不混入旧教师/旧协议模型权重。train24 基线只代表有限数据下的初步表现，不能与历史全发布数据实验直接作严格比较。

S0 只取 train 数据。验证过拟合用的同一小样本是调试证据，不计入泛化结果，也不据此选择教师。

### 6.2 固定起步配置

| 参数 | 本轮起点 |
| --- | --- |
| 主干 | d_model=240、4 层、6 头、FFN 倍数 4 |
| 动作窗口/步长 | 60/30 帧 |
| 时间注意力窗口 | 31 帧 |
| 状态 | 根平移 3 + 旋转 6D + 29 关节，输出解码为根位姿和关节角 |
| 扩散训练步数 | 1000，prediction_type=sample，clip_sample=False |
| 采样 | DDIM 25 步、eta=0、无 guidance |
| 优化器 | AdamW，lr=1e-4，weight_decay=1e-5 |
| batch | micro-batch=4，grad_accum=4，有效 batch=16 |
| 精度 | FP32；首轮不同时引入 AMP 或注意力后端切换 |
| 梯度裁剪 | 1.0 |
| 训练随机种子 | 20261008 |
| DataLoader | workers=4，每 worker 单线程；启动前验证进程和线程设置 |
| 起步训练预算 | 每模型 4,000 个 optimizer steps |
| loss 验证/完整生成验证 | 每 250 步/每 1,000 步 |

正式运行记录有效 scheduler 参数，包括 beta_schedule/start/end 等；配置中有字段不等于实际调度器已经使用。只对干净关节输出执行限位映射，不裁剪根或旋转，不裁剪前向高斯噪声。

### 6.3 损失

首轮复用当前可验证项：w_pos=1、w_rot6d=1、w_joint=1、w_geodesic=0.5、w_fk=2、w_vel=0.5、**w_contact=0**。

重建在已有标准化状态空间计算；旋转测地项单位 rad²；FK 项单位 m²；现有 vel 项是标准化状态的相邻帧差分拟合，不将其误称为物理速度约束。

接触项关闭时不执行手部 SDF/FK 分支，也不读取参考接触作为接触监督。现有 LossAssembler 在没有认证 mask 时回退到 batch.contact，且 w_contact=0 仍可能计算该分支；实施时需显式门控。不在本轮同时加入碰撞能量、Laplacian 或未标定接触项。

### 6.4 验证、选模与续行

- 不使用现有 CLI 的 val 前 60 文件或 Trainer 前 40 batches 截断作为正式验证。对全部准入 val originals 的训练窗口验证，并按有效样本/帧数正确加权。T1 使用冻结来源生成的 val 标签，W1 使用发布 val 标签；两模型的验证来源相同。
- 扩散去噪验证使用固定 t/noise 集，保存身份；验证 RNG 与训练 RNG 隔离，避免验证重置训练随机序列。
- 每 1,000 步在全部条件有效的 31 个 val originals 上生成完整轨迹，扩散采用固定采样 seed=7；以对选定来源标签的演示宏平均 teacher-fit FK MPJPE 选 best。不同教师来源的拟合值不作为同一真值的优劣比较。无效输出或缺标签计证据缺失；不能通过遗漏演示获得最优分数。
- 若没有覆盖完整集合的有效 checkpoint，记录“未取得合格 best”；last 可用于失败诊断，仍保留全部失败行，不能改称 best 或跳过数值错误。
- 另保存 root RMSE、关节 MAE、根旋转误差、人体任务误差和生成失败数；teacher-fit 改善不能替代裸输出的交互质量。
- T1 每模型首先完成 4k。若最后三次完整生成验证从最早一次到最后一次的宏平均 teacher-fit FK 误差降低 >=1%，且没有新增无效输出，则按原配置追加一个 4k 块；8k 时同规则最多追加到 12k。否则停止当前训练并交付结果。W1 每模型到 4k 即交付，不以更好地复现已知缺陷为理由自动延长。
- T1 的单模型上限为 12k，W1 为 4k；不在同一轮无界搜索学习率、网络或教师筛选参数。改实现、超参或数据另登记实验，不覆盖原尝试。
- 当无法计算上述宏平均（坏输出、缺教师或证据不足）时不自动延长，先排查原因；可以交付初步失败结果。

保存 best/last，以及有限的块边界 checkpoint。续训必须保存并核验 optimizer、步数、RNG、数据清单、统计量和数据顺序状态；现有只保存模型的 checkpoint 不视作精确 resume。若恢复条件不足，以 warm_start 的新实验登记，不拼接为同一次完整运行。

### 6.5 初步结果之后的有限选项

以下均不属于首轮默认执行：

1. **T2：扩大同来源。** local_preferred 时先由 train24 扩大到其余 train originals，使用同一冻结上游配置，重新拟合 train 统计并登记全部生成失败。随后才考虑增强；本地来源的增强须用该来源生成有效新标签，不能直接混入发布 rot/trans。W1 若考虑公开增强，继续明确弱监督用途。增强源/目标语义及变体采样权重分别核验，val 仍评估固定 originals。
2. **T3：可靠接触辅助。** 仅在能提供有版本的局部认证证据时，做 w_contact=0 与一个预先登记权重的比较。认证必须逐侧、逐区间验证，并结合穿透/限位/速度等局部有效性；原轨迹其他区间失败不能被局部接近掩盖。AABB 零距离不等于三 site 对真实 hull 接触，需先核查代理偏差和接触目标语义。mask 为空时贡献零损失/零接触梯度；缺证据时停在 T1。
3. **T4：针对性教师处理。** 按第 9 节触发条件，对少量 train 失败族比较已核实的上游配置调整或替代教师。自研局部修复只有在另立方案并取得相应能力证据后才列为候选，不能直接扩为全量自研重生成。

初步结果足以支持下一项实验时，记录选择理由和单变量比较，不要求先达到最终 90% 接受率才进行诊断。

## 7. 裸输出评估与独立验收

### 7.1 固定评估集合

在正式训练前冻结两级 val 集合：

- `val_originals_v1`：原 val 的全部 31 个原始演示，完整长度，用于生成拟合与最终裸输出检查。
- `val6_pilot_v1`：从原 val 按受试者各取一个演示，共 6 个，完整长度，用于详细接触、漂移分析和回放。每个受试者按 `SHA256("20261008|" + demo)` 排序取首个，不读取质量或模型结果进行选择。它是 val31 的固定子集，复用同一裸输出，不缩小整体质量评估分母。

保存具体名单与哈希，不只保存抽样规则。不能将已反复调试的 diagnosis6 或 calibration24_train_v1 当作新的留出评估集。

所有预期演示保留结果行。条件错误、短轨迹不支持、生成失败、检查超时、最终拒绝分别记录；不得替换成更易样本。teacher-fit 在教师数值无效时为缺失，人体任务指标在参考有效时仍可计算；不足完整证据时不作完整宏平均选模或优劣裁决。

上述是任务演示清单，独立于教师产物目录。T1 的 teacher-fit 参照为冻结本地来源的 val 标签；发布 val 轨迹另保留质量参照。标签生成失败不删除对应任务，不使用另一来源填补 teacher-fit。

主比较使用 sample seed=7。选定 checkpoint 的扩散裸输出另报告 seeds=7/17/27 的逐演示结果和变化范围；全部样本都计入，不按教师误差或验收结果选择最佳 seed。训练只有一个 seed，不将采样 seed 变化当成训练重复实验。

### 7.2 对照矩阵

| 方法 | 输入/处理 | 能说明什么 |
| --- | --- | --- |
| Teacher raw | 当前训练选定来源的标签直接回放 | 同来源教师拟合参照与实际质量 |
| Deterministic raw | 条件输入，一次预测，拼接 | 确定性生成质量与成本 |
| Diffusion raw | 条件输入，DDIM-25，拼接 | 扩散生成质量与成本 |

上述三方法在全部 val31 上保存完整裸输出及独立检查；详细曲线和回放另按固定 val6 汇总。默认不运行任何 `+ repair` 方法，不为取得非零通过率自动启用修复、平滑或投影。若裸输出已通过相关检查及实际任务要求，可直接使用；不合格结果只作诊断产物，不能标为可行交互输出。

在没有固定版本上游从条件重新生成的完整成本之前，不宣称相对 OmniRetarget 的端到端加速。教师生成、学习训练、模型在线生成及独立检查成本分别登记；裸输出推理速度不能替代合格轨迹的端到端效率。

T1 在 val31 额外保存 Published teacher raw 质量行，验证 train pilot 改善是否在留出任务上出现；它不替代选定教师、不参与参数回调。W1 的主教师就是发布数据，不重复计为独立方法。

### 7.3 独立验收冻结

首轮从 `load_mode_configs("strict")` 核查并保存实际 ValidationConfig、任务工作门和几何资产，直接对完整裸轨迹执行独立检查。默认不调用 RepairPipeline，不启用 regen_mode 或 R1/R2/R3 profile。不能用修复器的求解状态替代验收证据，也不能只保存 YAML 文件名。

当前标准路径的 task_mpjpe_tol_m 为 0.40 m。本轮将它明确标为**诊断工作值**，冻结后不因结果低而临时放宽。报告同时单列任务误差分布；历史 0.113 m 标定值带有选择偏差，可列为参照，不将其当作本轮已经重新标定的最终门。

保存 `robot_strict_pass`、`task_gate_pass` 和 `raw_standard_pass` 三项事实。裸轨迹数值有效、独立机器人 strict 检查及本轮工作任务门均通过，才记 raw_standard_pass；缺检查证据不得记通过。该状态只表示在冻结检查范围及诊断任务门下通过，不等于完整搬运任务达标。

双手认证与参考抓取的重叠帧、最长连续区间和累计漂移独立报告。参考要求双手抓取而输出没有对应认证区间时，持续抓握证据不足，不能利用“没有认证区间便没有手锚违反”宣称任务通过。最终可行交互结论仍需满足主方案的接触、任务及整段要求，本轮不新设更宽松的搬运准入门。

现有回放/修复常将固定输入箱体的 `box_ground` 对从机器人可行性裁决中排除。本轮必须保存 exclusions，额外报告固定箱体输入与地面的冲突：

- 输入箱体冲突属于场景输入问题，机器人修复不能通过移动已知箱体解决。
- 排除了 box_ground 的结果，只声明在已登记检查范围内的机器人轨迹通过，不声称完整场景无穿透。
- 其他碰撞族及插值检查不得为提高通过率而移除；保持既有允许对和检查范围。

生成候选和最终输出中的非有限/退化旋转都显式拒绝。有限次重采样仅用于数值退化，不按接触或任务分数挑样；保存实际尝试次数及最终有效性。验收失败保持原始轨迹与失败事实，不静默修改后再次记为裸输出。

### 7.4 指标

**拟合与任务指标：**

- teacher-fit：根位置 RMSE（m）、根旋转测地误差（deg/rad）、关节 MAE（rad）、机器人 FK 对教师 FK 的 MPJPE（m）。
- task：机器人对应关键点对参考人体关键点的 MPJPE，保存世界/目标物体系视图，报告均值、p95 和逐演示值；不使用 teacher-fit 冒充 task。
- 连续性：根/关节速度分布、拼接边界差分与段内分布、窗口累计漂移、完整长度和失败位置。

**质量与接触指标：**

- 教师与模型裸输出的穿透、限位、速度、脚支撑、手抓取检查；保留 failed_checks 及位置。
- 左/右手分别报告参考抓取帧、几何接近帧、认证总帧、认证与参考交集帧、最长连续交集以及累计锚漂。
- 双手同时认证交集帧数及最长连续区间单列；单手认证和近箱不能替代双手搬运证据。
- 接触 F1 报 defined 数量和未定义情况；没有认证区间不能获得“持续抓握通过”的结论。

**检查与成本指标：**

- 每个方法 expected、processed、raw_standard_pass 数量、rejected、timeout、error；处理数与集合身份必须完整对账，接触证据单列。
- 整段诊断检查通过率及失败类型；只通过机器人/任务工作门而缺乏双手搬运证据的轨迹不能计为主方案成功。
- 在线总耗时包含条件构建、生成全部去噪调用、拼接、独立检查和所有数值重试；GPU 计时按边界同步，记录预热和冷/热缓存。
- 报告全预期集合总耗时、诊断检查通过轨迹/小时，以及共同通过样本上的配对质量和耗时；这些指标不宣称最终任务效率。共同集合为空时为 undefined，不能通过只统计通过样本制造加速。

以原始演示为宏平均单位。窗口、帧和扩散多次采样不作为独立演示数；可同时报告帧加权值，但必须标明。

### 7.5 最终测试边界

本轮主要交付 val 的初步结果，不默认执行 test。模型、教师协议、评估代码及最终输出方法冻结后，另登记最终测试执行。

旧 24 段历史标定含 19 train/2 val/3 test，此外历史审计或回放可能暴露更多 test。整理每个原演示的历史使用与暴露清单；未能追溯的状态记 unknown，不宣称该 test 完全未见。已有分组保持，不为了恢复“干净测试”叙述而重洗演示。

### 7.6 后续可选修复诊断

本轮默认记 `repair_comparison=not_planned`，不运行训练前修复能力试验或原六方法修复矩阵；这些项目不属于训练就绪门、阶段 E 完成要求或默认预算。

若后续已有明确的新能力证据和诊断问题，再另登记固定 train 用例、完整分母、配置及有限预算，比较 Teacher raw/+repair 或模型 raw/+repair。采用标准修复时锁定 `regen_mode=False`、无 R profile，保存实际 RepairConfig 与 ValidationConfig；报告求解接受、独立检查、任务工作门和接触证据。`accepted_standard` 仅保留为该可选修复实验的诊断状态，不能与 raw_standard_pass 混成最终任务接受率。

Teacher + repair 使用离线教师机器人初值，不能作为仅输入人体条件的可部署纯优化计时基线。求解失败不证明物理无解；成功也不证明所有教师或预测都可修复。修复器调参、替代优化器及整段可行输出方法开发须另立方案，不自动回调本轮 val 或延长动作训练。

## 8. 分阶段执行与出口

| 阶段 | 必须完成的工作 | 出口与失败处置 |
| --- | --- | --- |
| A1：冻结与配对 | 来源/资产/原分组核验、pilot 六段场景映射、val 名单、协议和输入哈希 | 身份/条件不可靠先修，pilot 名单固定 |
| A2：上游教师比较 | P/U0 及已预注册 U1 的完整六段生成、质量与成本比较 | 写 teacher_selection；local_preferred/no_quality_gain/incomplete/not_ready 分列 |
| A3：小批标签 | local_preferred 的 train24+val31 生成和质量登记；或明确 W1 用途及发布数据基础审计 | 来源、配置和分母固定，不要求全部 strict，不填标签洞 |
| B：数据与接口 | 选定协议/清单入口、独立缓存及 train 统计、显式配置 CLI、评估完整长度支持 | 数据可追溯，加载与推理条件一致，无监督条件泄漏 |
| C：数值烟测 | train 小集合，双方至少 100 optimizer steps；小样本重复拟合至多 1,000 步 | 输入/梯度/损失/输出有限；小样本重建趋势合理，失败先定位代码/条件 |
| D：初步训练 | T1-D/T1-F 各 4k 并有限续行；W1 替代分支最多 4k；完整 val 选模 | 两模型 checkpoint、曲线和完整生成验证；失败可以作为证据交付 |
| E：初步结果 | val31 三方法裸输出对照、T1 发布教师参照、val6 详细分析、成本及逐演示失败证据 | 固定集合全对账，报告学习结果和质量缺口；不要求检查通过数>0 才能结束 |
| F：路线判断 | 按 §9 定位主要瓶颈，确定维持训练、扩大同来源、教师处理或另立可行性方法方案 | 形成有证据的下一实验；不自动启动修复器开发、其他教师或全量生产 |

正式训练就绪门：A1/A2 来源比较与身份核验完成、训练来源/用途裁决明确、A3/B 正确性通过、当前 production_cohort 每个预期演示有结果行、六受试者各有可用训练窗口、训练数据量满足实际 batch、C 完成。T1 的小批目标为 24 个 train 演示，实际准入数量和生成失败如实记录；不要求其余 226 个 train 教师已生成。若某受试者完全没有可用窗口，先解释原因；更小集合只能标调试结果。

该门不包含旧 6/6、18/24、所有教师 strict 通过、修复能力试验或最终接受率 90%。训练集数量和覆盖不足仍需如实说明，不能将“能够训练”解释为“数据已充分”。

E 的完成要求是完整、可核验的裸输出比较证据。诊断检查全拒时交付 0/N 及失败分类，不因结果为零启动修复调参，也不删困难演示。预算中止或缺默认方法时标 INCOMPLETE，不写完整比较通过；可选修复项目 not_planned 不影响本轮完成。

若 E 显示裸输出不能满足可行交互要求，F 明确登记“动作基线完成/失败，最终可行输出方法尚未就绪”。可以据此结束本轮；后续投入须针对已有质量缺口说明收益，不能自动把责任交给自研修复器或假定扩大训练会解决教师已有缺陷。

## 9. 何时处理或更换教师

### 9.1 诊断与下一动作

| 观察到的现象 | 优先解释与动作 | 教师替换条件 |
| --- | --- | --- |
| 小样本也拟合不了 | 检查条件、编解码、梯度、数据顺序和优化实现 | 不由此触发换教师 |
| train 拟合好、val 明显变差 | 过拟合、覆盖、条件一致性；优先扩大同来源原始演示，再考虑增强 | 除非证实该来源缺少所需任务覆盖 |
| 生成对教师误差仍在明显下降 | T1 按有限预算继续；W1 到 4k 交付诊断 | 尚无必要性证据，但拟合改善不消除已知标签风险 |
| 选定教师与模型仍复现同类滑移/悬浮/漂移 | 结合前置来源比较与当前误差量级，评估残余标签缺陷 | 已知教师缺陷不必重新由模型证明；改变其他教师路线仍需说明收益 |
| 教师裸输出较好，模型新增明显穿透、滑移或边界突跳 | 预测误差、条件或拼接问题；先检查学习与推理实现 | 不默认换教师，也不默认启用修复 |
| 模型拟合教师，但裸输出仍不满足交互要求 | 当前动作监督及可行性处理不足；登记最终输出方法未就绪 | 另立教师改进或可行性方法实验，不无界延长拟合 |
| 诊断机器人/任务门通过但双手认证证据不足 | 检查范围的通过不能代替完整搬运要求 | 根据实际接触缺口判断教师用途，不宣称任务成功 |
| 固定箱体输入与地面冲突或明显不可达 | 输入场景/任务范围，显式拒绝和登记 | 需改变任务设置，不能只换机器人标签 |

teacher-fit 误差小没有统一的任意数值门：结合根、关节、手部 FK 和教师缺陷幅度判断。发布教师的悬浮等缺陷已是前置已知风险，不能再次默认“先训练后才允许确认教师有问题”。要将残余标签缺陷列为当前模型交互质量的主瓶颈，至少提供 **3 个不同 train 原始演示** 的同族证据，逐例比较 Teacher raw 与模型 raw，说明预测误差与教师缺陷的量级，并核查条件与实现。三例用于避免单例误判，不构成总体统计证明；该归因不要求修复器先失败一次。

### 9.2 小规模教师比较的要求

§3 的前置 OmniRetarget 来源比较按固定六段执行；本节指初步结果之后的下一轮比较，不要求先训练才能执行 §3。触发后另登记最多 12 个 train 原始演示，覆盖失败族和同类成功对照；固定目标物体、模型资产、原分组和输出验收口径。优先检查已查实的上游能力，再按证据比较其他生成方法。自研局部修复须先有另立实验的能力证据，不能视为默认可用候选。先改变一个因素，避免全量替换后无法归因。

比较至少报告：原始分母、可用动作时长/窗口、可靠双手监督量、任务误差、全成本、失败分布和所需标签修改。要声称新教师更有训练价值，还应在可比数据覆盖和训练预算下比较模型裸输出的学习与交互质量，而不能只比较离线接触指标。若另有可行性处理实验，单列其结果与成本。

教师候选配置的质量选择只接触 train；选定配置可在 val 上固定生成标签供学习评估，不利用 val 标签质量回调教师配置。test 不用于筛选。旧教师、新教师、局部修复和增强保留来源与父演示关系。发生更换时保留 T1 或 W1 的模型、数据清单和结果。

### 10.3 有意义的测试

5. w_contact=0 不执行接触分支且无接触梯度；开启时缺证据拒绝或按已登记的全零 mask 处理，不回退人体参考标记。
6. 验证不污染训练 RNG，验证覆盖和加权正确，保存的 best 确来自完整生成指标；空/坏输出不改善选模分数。
7. 全长度包含最后窗口；一个生成失败/一个超时仍保留 expected 分母；最后输出非有限或退化不能 raw_standard_pass。
8. 同一数据与 checkpoint 的确定性生成复跑一致，扩散固定 seed 可复现；计时含全部采样调用和失败尝试。
9. 上游输出改变目标箱体、T/fps、源参考或资产时比较拒绝；生成失败/超时保留 pilot 分母，不能通过只计算成功子集判优。
10. 本地结果无改善、指标退化、双手分母为空、穿透被接近阈值误计、缺失质量行等反例不得 local_preferred；U1 未预注册不能执行。
11. W1 不能自动续到 8k/12k；本地教师缺失不能回退发布标签；两种来源的同 demo 缓存及统计不能互相污染。
12. 默认评估不调用 RepairPipeline、不平滑或投影裸输出；独立检查失败保留原轨迹，缺认证区间不能变成双手搬运通过，可选修复未计划不阻塞阶段 E。

实施时先跑相关测试，代码冻结前执行 `uv run --locked pytest tests/ -q`，记录实际结果。359 passed+1 skipped 为最近工程验收快照，不预设本轮测试总数。本次文档修改只做 diff、引用和结构检查。

## 12. 资源预算与停止条件

### 12.1 起步预算

预算是运行上限与调度建议，不是时间保证：

| 工作 | 起步运行预算 | 达到上限后的处置 |
| --- | --- | --- |
| 上游环境与真实 API 烟测 | 1 小时 | 登记安装/环境/适配问题，不当作标签质量失败 |
| pilot 配对、清单与新缓存 | 2 小时 | 分段保存已处理数；缺项不宣称就绪，按实测登记剩余工作 |
| 教师六段比较 | U0 最多 3 小时；需要且已预注册的 U1 再最多 3 小时 | 全预期结果/失败对账；超时为 incomplete，不自动判优或回退 |
| local_preferred 小批生产 | train24+val31，按 pilot 全成本估算，起步 6 小时 | 保留完成/失败/未运行行；不等待 train250，不修改配置补洞 |
| S0 数值烟测与小样本拟合 | 合计 1 小时、每模型最多 1,000 步 | 不通过先定位实现，不启动全数据训练 |
| T1 或 W1 训练 | T1 每模型首块 4k、最多 12k；W1 每模型最多 4k；累计 GPU 墙钟上限 12 小时 | 按对应路线续行；到上限保存 last 和 incomplete，不追加超参搜索 |
| val31 裸输出与质量登记 | 三方法及 T1 发布教师参照，起步 2 小时 | 保留逐方法进度，未完成不能称完整裸输出比较 |
| val6 详细分析与回放 | 复用 val31 裸输出，起步 1 小时 | 不删长段、不改阈值；缺详细证据记 incomplete |

上表只限制实验运行资源，接口开发和正确性修复的工时另记。GPU 训练墙钟包含该训练过程中的验证；数据审计、独立检查和最终回放成本另列，不把阶段预算当算法耗时。本轮默认 repair 运行次数为零，取消原 18 次 repair/6 小时预算，不将该预算自动转为修复器调参或替代算法开发。

先测完整 pilot 上游生成的全成本，再估计本地小批生产；发布轨迹回放成本不能替代生成成本。首个 200 步测量当前训练 ms/optimizer step、峰值显存、验证额外成本。首个完整 val 裸轨迹生成与检查后更新剩余预算估计并记录，不从某个异常负载点直接外推全天。预算调整只改变资源上限，另登记理由，不新增实验候选或样本筛选。

后续修复诊断或替代可行性方法按 §7.6 另登记目的、固定集合和预算；本轮完成后不自动启动。

### 12.2 本机配置与存储

沿用 Python 3.12.x、项目 `.venv`、`uv run --locked`；新增依赖按实际缺口通过 uv 维护，首轮优先现有 NumPy/SciPy、MuJoCo、pytorch_kinematics、PyTorch/Diffusers 和 threadpoolctl。

单张 RTX 3090 24 GiB，训练 sequential。起步 micro-batch=4、累积=4；OOM 时先减少 micro-batch 并增加累积维持有效 batch=16，保存变更。独立数值检查与对拍按现有 float64 路径。预处理先 workers=4、native_threads=1；实际采样检查是否有收益，再决定并发。

大量写入和训练前重新检查磁盘、GPU 与 CPU 占用。检查点保留 best/last 和有限块边界，避免逐步存档；缓存按 clip 保存。失败 trace 只对代表性冻结用例保存完整数值，其余保留足够定位的摘要，防止再次形成无界产物。

### 12.3 停止与错误分类

- 身份/配对/条件泄漏、数值坏值或源文件修改：停止相关阶段，修正确性并重验受影响结果。
- 无有效数据或不足构成 batch：数据就绪失败，报告实际覆盖，不用空 loader 或空验证获得零损失。
- worker 崩溃、GPU OOM、磁盘不足：工程失败或 incomplete，不记运动学不可行。
- 裸输出验收失败：保存具体失败位置、质量和原轨迹，不启动默认修复或自动修改教师。
- 完整结果均拒绝：可完成本轮动作学习诊断交付；最终可行交互目标仍未实现，不宣称方法达标。
- 后续可选修复拒绝、无 merit step、信赖域塌缩：只属于相应独立实验，不自动改教师、求解参数或阻塞本轮动作训练。
- 上限到达：保存实际消耗与剩余 expected，复用完整任务，禁止部分集合 PASS。

## 13. 初步结果的交付格式

报告至少包含以下相互对应的证据：

1. **来源决策和数据表**：pilot 六段 P/U0/U1 对照、真实差异、质量改善/退化与裁决；小批生产或 W1 的候选/准入数量、split/subject 时长、独立演示和窗口、生成失败/排除原因、质量检查完成度。
2. **训练表与曲线**：两模型配置、步数、验证选模、数值失败、峰值显存、训练/验证成本，明确是否仍在改善。
3. **val31 裸输出表**：教师拟合、人体任务误差、拼接与完整几何检查，逐演示及宏平均，多采样变化范围。
4. **val6 详细表**：复用主比较三方法及 T1 发布教师参照，记录 expected/processed、诊断检查通过/拒绝、逐类失败、接触与双手认证、漂移和总成本；修复对照默认 not_planned。
5. **代表性回放**：至少 3 个不同 val 演示，按诊断检查通过/失败类别确定性选取，展示人体、固定箱体、教师和模型裸输出；全部失败时仍展示失败及位置，不制作只有通过样本的演示集。
6. **路线判断**：继续当前训练、扩大同来源、条件问题、教师处理、可行性方法未就绪或证据不足；每项判断指向具体清单/结果。W1 的失败不能改写为“高质量教师仍无效”，本地 pilot 的改善不能冒充全库或留出集改善。明确动作基线与最终交互目标各自的完成状态。

初步成功的含义是得到可靠且有解释力的动作学习基线，不自动代表严格可行交互、可承重抓握、动力学可行、RL 可跟踪或真机部署。没有有效修复方法且裸输出不合格时，交付失败证据并停止本轮；不得以“未来修复器可以兜底”改写结论。
