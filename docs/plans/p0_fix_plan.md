# P0 审阅修复方案

日期:2026-09-14。状态:**已实施并验证**(同日;实施记录与全部重测结果见 [p0fix_verification.md](../verification/p0fix_verification.md);本文件保留为原始方案,完成清单逐项核对于该记录)。原始定位:依据当时代码审阅、只读数值探针及 [P0 验证记录](../verification/p0_verification.md)制定。

## 1. 目标与边界

解决四项问题:手部推断速度坐标系错误、修复后质量评测缺失、转移检查遗漏箱体运动、终检失败定位不完整。完成后重新评估 P0.1/P0.2/P0.3,保留负结果。

- 保持现有 strict/relaxed 容差、参考接触调度、训练缓存和模型权重。不得为恢复原接受率追加放宽。
- 本轮不推进教师重生成、模型重训、持久 QP 工作区或跨机器人扩展。
- 旧报告及产物保留为历史记录。新产物记录代码版本、完整有效配置、输入清单、随机种子、模型校验值和筛查排除项,文件名区分模式与任务门槛。
- 原 strict 2/6、relaxed 4/6 和 P0.3 数字暂视为旧实现结果,不能直接沿用为修复后的基准。

## 2. F1:手部准静态推断使用箱体系速度(P1)

### 修改

位置:`src/ireset/repair/validation.py::_infer_robot_schedule`。

1. 将手速来源由世界系 `hand_pts[s]` 改为已缓存的 `hand_local[s]`,逐 site 差分取范数最大值,除以 dt。该坐标系与 `_check_hands` 相同,同时消除箱体平移和旋转贡献。
2. 保留首帧无速度证据、双阈值和最短区间规则,保持当前快速相对运动作为过渡的语义。本轮不另改进入/退出状态机。
3. 补充输出推断到的手部接触帧数/区间数。零接触区间不等于抓握质量已获认证,报告中应可辨识。
4. 更新说明中的“相对速度”定义;不能再以世界系手速较大解释教师手部不锚定或验证器无抓握区间。

### 回归验证

- 固定手-箱相对关系,分别施加共同平移和共同刚体旋转;手部区间、箱体系锚漂及相对速度结果应保持不变。仅要求手部检查不变,世界系脚支撑不满足该不变性。
- 用受控距离 mock 隔离推断逻辑,再用真实 MuJoCo FK/几何状态做集成对拍,避免只验证数组公式。
- 慢速箱体系漂移保持在推断速度门内,累计超过锚漂门后必须拒绝;快速相对运动按现有过渡语义处理。
- 重现审阅探针:共同平移 0.3 m/s、箱体系手速近零时,抓握区间不再消失。

**验收:**推断与检查使用同一箱体系;共同运动不删除有效抓握。修复后教师手部检查可能重新生效,不得预设旧 relaxed 接受率不变。

## 3. F2:转移检查使用完整前后场景(P2)

### 修改

位置:`repair/scp.py::FrameContext`、`repair/pipeline.py::_frame_ctx/frame_valid`。

1. 在帧上下文增加可选 `box_pose_prev`,t=0 为 None,其余取固定输入箱轨迹上一帧。顺序循环和后缀重试均传递该值。
2. 前场景由 `z_prev + box_pose_prev` 构造,后场景由候选状态与当前箱姿构造。运动量使用终检现有的 `_frame_motion_m`,并尊重 `check_interpolated_states` 开关。
3. 沿用终检分段数量和 SLERP/线性插值规则。每个探测点实际使用插值箱姿,不能只取插值机器人状态后继续使用当前 `ctx.box_pose`。
4. 区分端点检查与转移检查:端点仍执行现有完整约束和任务门;转移采样对齐终检的碰撞检查范围、排除项和穿透容差。不要把相对于前帧、按完整 dt 定义的速度行或端点锚点行无条件施加到中间态。
5. 保留独立终检的全碰撞对扫描,不依赖求解器活动对缓存。可复用确定性的采样小函数,不让验证器依赖 SCP 状态。

### 回归验证

- 机器人不动、箱体平移穿过机器人:端点无碰撞,中间碰撞必须被转移检查发现。
- 箱体仅旋转造成中间碰撞:旋转运动量与探测点均须生效。
- 机器人和箱体共同运动,相对位置不变:不得因把前帧机器人配上后帧箱姿产生虚假碰撞。
- 对同一对完整场景,比对顺序检查与独立终检的细分数量、探测场景和碰撞结论;覆盖阈值以下、阈值以上、细分上限及禁用插值。

**验收:**在同一采样协议下转移碰撞结论一致;保留细分上限及实际检查间隔报告,不宣称连续时间零穿透。

## 4. F3:结构化记录最早失败位置(P2)

### 修改

位置:`repair/validation.py::CheckResult` 及各检查函数、`repair/pipeline.py::_first_failure_frame`。

1. 在 `CheckResult` 末尾追加默认 None 的 `first_failure_frame` 字段,兼容现有位置参数构造。人类可读 `location` 保留最差值定位,重试不再解析显示字符串。
2. 各检查分别记录最差位置与首次越界帧。脚漂移相对区间起始锚逐帧计算;手锚漂移相对 `iv.anchor` 逐帧计算。不能把手锚违例定位到区间起点,也不能遗漏脚漂移帧号。
3. 速度违例归属差分后帧;插值碰撞归属区间右端帧,使重试包含需要改变的转移。有限性、四元数、限位和碰撞检查采用一致约定。
4. `_first_failure_frame` 对全部失败检查的有效帧号取最小值。通过的检查不参与;失败但无定位时采用保守的全段重试,避免默认重试末尾掩盖定位缺失。
5. 保留一次重试上限。输出首次失败帧、最差帧、实际重试起点与前后失败原因;计时包括两次尝试和终检。

### 回归验证

- 单独的慢速脚漂移失败能返回首次超过门槛的帧。
- 手锚漂移在区间后半段超限,首次越界帧与区间起点、最差帧可区分。
- 多个检查以不同插入顺序返回不同失败帧,始终选择时间最早者。
- 覆盖帧 0、插值区间、仅末帧失败、无定位失败和全部通过。
- 用可控求解器替身验证后缀重试范围、前缀重放行为及重试次数;真实场景最终仍须通过独立终检。

**验收:**重试位置由结构化首次失败证据决定,不受检查项顺序或显示文本影响。

## 5. F4:修复后闭环评测与可追溯产物(P1)

### 修改

位置:`scripts/eval_generation.py`、`scripts/eval_repair.py`,按需要新增小型指标汇总函数。

1. 保留裸输出质量用于生成模型诊断,显式命名为 `raw_metrics`。接受轨迹重新计算 `repaired_metrics`,拒绝轨迹不构造 MPJPE。
2. 明确比较对象:任务 MPJPE 为目标物体系下 G1 对应关键点相对参考人体关键点的误差,与修复器任务门口径对拍;机器人对教师 FK 的 MPJPE 单独标为教师拟合误差,不能代替任务指标。
3. 裸教师指“无噪声教师作为修复输入”;基线质量取其修复后的接受轨迹。使用同一批 val original、帧区间、模式、任务门槛与筛查规则。可复用基线产物,但必须校验这些元数据及代码版本;不匹配时重跑。
4. 对每个方法按 demo ID 与教师基线求接受集合交集,逐样本计算任务 MPJPE 差,报告配对均值、差值及 n。n=0 时条件为未定义。不得把模型全部成功数作为配对数。
5. 修复后重新推断接触并计算手部 F1。分别报告接受集原始值和预登记全集成功加权值(拒绝记 0),左右手与演示宏平均口径明确。沿用双空未定义策略,同时列出有效/未定义样本数;不得静默填 1。
6. P0.3 条件逐项列出:接受率不低于教师基线、配对 MPJPE 不高于基线 +2cm、成功加权手 F1 不低于教师基线的 0.95 倍。任一指标缺失或未定义都不能判为通过。
7. 补齐修复幅度(根平移/旋转、关节 RMS/max)、slack 帧占比、失败分类与端到端耗时均值/p50/p95/max。记录 slack 使用为独立事实,不能仅从 `repaired_prev`/`repaired_bt` 等路径名称推断;核查求解器所有成功返回分支保留 `slack_used`。
8. 计时覆盖预处理、生成、修复、回退与终检,拒绝案例保留。分阶段计时用于诊断,不能代替端到端计时。
9. JSON 和接受 NPZ 记录有效配置与输入身份;默认输出名带 strict/relaxed 和门槛标识,避免覆盖旧实验或混用 0.101 与 0.40。

### 回归验证

- 构造方法接受 {A,B}、教师接受 {A,C} 的汇总用例,配对 n 必须为 1;无交集为未定义。
- 修复改变了关键点和接触时,`raw_metrics` 与 `repaired_metrics` 分别来自正确轨迹。
- 拒绝样本进入接受率/F1 分母,不生成位置误差;覆盖双空未定义接触。
- 验证基线元数据不一致时拒绝复用,有效门槛写入产物。
- 端到端计时包含首轮失败和重试;slack 经多起点或回溯后仍能正确计数。

**验收:**报告可由保存的逐样本产物复算;原报告 8.2cm/11.0-11.1cm 明确归为裸输出教师拟合误差,不再用作闭环任务质量达标依据。

| 阶段 | 工作 | 完成条件 |

P0.2 重标条件:新终检与修复器改变了接受集,旧标定不再可迁移。保留原 0.101 作固定对照,仅在登记集及接受样本覆盖满足原方案时按 p95+0.02 重标,并记录选择偏置。不能在 8 段闭环结果上调门槛。

本轮不要求重训模型:模型权重和输入条件未改变。后续若另改参考接触调度或训练标签,应单独评估缓存重建及重训范围。
